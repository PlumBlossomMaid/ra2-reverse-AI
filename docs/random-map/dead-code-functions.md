# RMG 死代码函数取证（22 个零引用函数）

> 目标：判定 `rng-ledger.md` §二 那 22 个零引用函数"原本属于什么"。
> 前置条件已满足（104 活取数点全还原 + 端到端逐字节闭环）。
> 取证手段：`disasm.py`（capstone 直反汇编）+ callgraph `functions.tsv`/`direct_edges.tsv`
> + `xref_abs.py`/`xref_rel32.py` 双工具独立复核。**不依赖 Ghidra 的函数边界。**

## 结论摘要

1. **「死代码」判定成立**——`xref_abs.py` 与 `xref_rel32.py` 两个独立工具都报
   0 处引用，与 `functions.tsv`/`direct_edges.tsv` 的零入边一致。即：函数体完整
   存在，但整个 4MB 镜像里没有任何静态引用。

2. **「疑似整套地形生成方案」这一假设不成立**——已取证的函数是**实体布置**
   （在随机合法格子上放建筑/单位），全程不碰 tile/level/ramp 等地形字段。

3. **规模比原估计大一个量级**：全表 8655 个函数里 **2706 个零调用（31.3%）**，
   占 `function_bytes` 的 **20.8%**（541927 字节）。原「22 个」是「有取数点且
   零引用」这一窄口径的子集。

4. **`0x5A1E10` 是本轮最重要的发现**：死代码区里躺着一份**与活代码 MapType 3/4
   分支平行的一套编排**（含 `RepaintAll(Instance, -1)` 的 `push -1` 实参形态，
   与 `0x598D73` 实锤一致）。它把「被什么替代了」的答案从「另一套地形方案」
   改写成「**另一套同分支编排**」——原版为同一分支写过两版，链接器留下一版。

5. **不是 TS 时代遗物，而是 YR 自己的 MapGen 层代码**：与活代码共用同一套
   全局与惯用法（`Randomizer @0xABE890`、work 数组 `@0xABED10` 每格 0x50、
   边长 `@0x89C2DC`、同一套 `scaled_random` 拒绝采样）；且
   **`0x597380` 已铁证归属 MapGen.cpp**（体内 `push 0xF5E`(行 3934) +
   `push 0x82BA48`(MapGen.cpp 字符串 VA)）**同时**零引用——「同一 TU 内含
   零调用函数」已是**已证事实**，链接器未开 `/OPT:REF` 即可解释零散分布。
   ⚠️ 「死代码区间 `0x58BE20-0x5A8F00` 全属 MapGen.cpp」仍是推断。

6. **它们是一棵有序的编排树，不是零散残留**：`0x5A5020`(827B) 与 `0x5A80B0`
   (546B) 两个零引用根按固定顺序串起 `0x5A5360`→`0x5A5B50`→`0x5A6510`→
   `0x5A6920`→`0x5A78D0` 与 `0x5A89D0`→`0x5A82E0`→`0x5A8720`，二���都直接
   读 `[0x89C2DC]`/`[0xABED10]`/`Randomizer` 三样核心设施。⚠️ 「最终启用了
   另一套」是推断——零引用只证明静态不可达。

7. **【0xABED04】/`[0xABED08]` 已实锤**（解掉 `0x5A7250` 一节的待查）：
   写入点在活代码 `0x566306`/`0x566317`——
   `mov [0xabed04],eax`（eax=`[0x87F8DC]`=W）、`lea eax,[eax+edx*2]`（W+2H，
   edx=`[0x87F8E0]`）、`mov [0xabed08],eax`。即 **`[0xABED04]`=W、
   `[0xABED08]`=W+2H**（菱形等距坐标的最大行宽）。二者合计 107+88 处引用，
   从 RMG 区一路到 `0x6B4xxx`，**不是死代码专有全局**。

8. **三份 117B 函数是同一源码的独立编译副本**：`0x5A2ED0`/`0x5A4AE0`/`0x5A4FA0`
   按指令边界归一化后两两逐字节相同，唯一差异是各自私有的 5.0 常量副本地址。
   **5 个「两锚点距离/角度 + 随机抖动」函数**（上表）构成一个完整的插值原语集，
   其中 `0x5A1190` 做 atan2 象限归一化、`0x59D480` 把距离窄化到 **float**。

9. **符号名不可当铁证**：`BuildingClass::BuildingClass` /
   `IsWithinUsableArea` / `GetFireError` / `AStarAttempt` 的 `symbol_source` 全为
   **`USER_DEFINED`**（YRpp 开源符号覆盖，非本 exe 实锤）。本文档所有带类名的
   调用一律视为「推断名」，实锤的只是地址。

10. **callgraph 数据缺陷已修复**（2026-10-14）：`functions.tsv` 原把 11 个
    函数记为 `body_bytes=1`（实测 107–546 B），已按实测长度回修
    （`body_max=entry+len-1`）。引用计数与函数体大小现在都可信
    （引用计数双工具复核过，函数体大小反汇编实测过）。

11. **两个系统性筛选盲区**（都超出个别函数）：
    ① **零取数**的辅助函数被「按取数点分组」口径漏掉
    （`0x5A6BA0`/`0x5A1E10`/`0x5A3A60` …）；
    ② **被死代码内部调用**的辅助函数 `unique_callers≠0`，因而不进零调用统计
    ——`0x5A6C10`(被调 15 次)/`0x5A7250`(7 次) 即是，却同样属这套废弃方案。

## 数据质量问题：11 个函数被 Ghidra 误判为「1 字节函数」

`functions.tsv` 把下列 11 个记为 `body_bytes=1` 且出入边全 0：

`0x58BE20` `0x58C320` `0x58C4A0` `0x58C5A0` `0x59D480` `0x5A1190`
`0x5A2ED0` `0x5A4AE0` `0x5A4FA0` `0x5A5AE0` `0x5A80B0`

**这是错的。** 用「反汇编到第一个 `ret`」实测 11 个函数真实长度，**没有一个是
1 字节**：

| 地址 | 真实长度 | 内部调用特征 |
|---|---|---|
| `0x58BE20` | 126 B | `Random` + `_ftol` |
| `0x58C320` | 142 B | `Random` + `_ftol` |
| `0x58C4A0` | 231 B | + `GetCellAt(0x5657A0)` + `0x486380` |
| `0x58C5A0` | 259 B | + `GetCellAt` + `0x56D230` + `0x486380` |
| `0x59D480` | 137 B | `0x4CAC40` + `Random` |
| `0x5A1190` | 210 B | `0x4CADE0` + `Random` |
| `0x5A2ED0` | 117 B | `0x4CAC40` + `Random` |
| `0x5A4AE0` | 117 B | `0x4CAC40` + `Random`（与上**同构**） |
| `0x5A4FA0` | 117 B | `0x4CAC40` + `Random`（与上**同构**） |
| `0x5A5AE0` | 107 B | 只有 `Random` |
| `0x5A80B0` | 546 B | 12 个 call，第二个零引用根 |

`rng_ledger.txt` 记的取数点（`58BE48`/`58BECB` 等）落在实测函数体内，与反汇编
吻合——**是 functions.tsv 的边界识别错了，不是 ledger 记错**。

⚠️ ~~**形态推测（未实证）**：`0x5A2ED0`/`0x5A4AE0`/`0x5A4FA0` 长度相同、调用特征
相同，疑为**同一辅助函数的三份复制**。~~ → **2026-10-13 已实锤**：按指令边界
归一化后两两逐字节相同，确为同一源码的三份独立编译副本（唯一差异是各自私有的
5.0 常量副本地址）。短小且高度重复的函数形状，正是 Ghidra 边界识别器容易退化
成 1 字节的情形——这与「11 个全被判 1 字节」的现象吻合。

⚠️ 影响面：这批 callgraph 数据后续被 frontier 流程当基准用。凡依赖
`functions.tsv` 的 `body_bytes`/`unique_callers` 做筛选的地方，对这 11 个地址
都可能得出错误结论。**引用计数本身仍可信**（xref 双工具独立复核过），只是
函数体大小不可信。

## 已确认的函数语义

### `0x58BE20` —— 随机取一个「已占用」的格子

```
eax = [0x89C2dc]（边长 side）；eax = side*side；esi = side*side - 1
scale = (double)(side*side)
loop:
  v = _ftol( (double)(uint32)Random() * scale * [0x7ed898] )   // = *total/4294967295.0
  if (v > side*side-1) goto loop;                               // 拒绝采样
  p = [0xabed10] + v*0x50                                       // lea ecx,[eax+eax*4]; shl ecx,4
  if (p->x == 0 && p->y == 0) goto loop;                        // 空格子 → 重抽
  *this = *p;  return;
```

- `side*0x50` 的索引方式与活代码（`0x578E60` 分配 side²×0x50）同一套。
- 返回值 = `work[v]` 首 dword，即 `x | (y<<16)`。
- 同地址 `0x58BEA0` 是同构的第二份（同样 prologue、同样惯用法）。

### `0x5A6510` —— 按派生区间取随机槽位，再除 2 传下去

```
n = arg->[0x10] / 10        // imul 0x66666667; sar edx,2   => >>34
m = arg->[0x10] / 5         // imul 0x66666667; sar edx,3   => >>35
hi = n - m + 1 ; lo = m
loop:  v = _ftol( (double)(uint32)Random() * hi * [0x7ed898] + lo )
       if (v > n) goto loop;
       FUN_005ad6f0( v >> 1, 0, 0, &out )
```

⚠️ `n`/`m` 的关系在正数下 `m > n`（`x/5 > x/10`），区间方向存疑；
需确认 `arg->[0x10]` 的取值域才能定语义。**暂标 partial**。

### 「两锚点距离 + 随机抖动」四件套（同源模板的多次实例化）

这一族共 5 个函数，入参一律是**两个格子坐标对**（各以 `movsx word` 读
`x`/`y` 两个 int16），返回 `double`。

| 地址 | 长度 | 公式 |
|---|---|---|
| `0x5A2ED0` | 117 B | `euclid + Random()*5.0/2³²` |
| `0x5A4AE0` | 117 B | 同上（独立副本） |
| `0x5A4FA0` | 117 B | 同上（独立副本） |
| `0x59D480` | 137 B | `Random()*10.0/2³² + 0.5*arg − 0.02*euclid` |
| `0x5A1190` | 210 B | `2.0*Random()/2³² + 1.5*∠(p2−p1)` |

**2026-10-13 实锤：三份 117B 是同一源码函数的独立编译副本。**
按指令边界（capstone）归一化掉 `call rel32` 与 `fmul qword [imm32]` 的立即数
后，`0x5A2ED0`/`0x5A4AE0`/`0x5A4FA0` **两两逐字节完全相同**：

```
0x5a2ed0 -> call 0x4cac40 / call 0x65c780 / fmul [0x7ed7c0] / fmul [0x7ed898]
0x5a4ae0 -> call 0x4cac40 / call 0x65c780 / fmul [0x7ed800] / fmul [0x7ed898]
0x5a4fa0 -> call 0x4cac40 / call 0x65c780 / fmul [0x7ed808] / fmul [0x7ed898]

归一化后 0x5A2ED0 vs 0x5A4AE0 : 完全相同
          0x5A2ED0 vs 0x5A4FA0 : 完全相同
```

唯一差异是抖动系数常量的**地址**，而三个地址里的**值都是 5.0**
（`0x7ED7C0`/`0x7ED800`/`0x7ED808` 三份私有副本）——编译器没有合并同名常量
字面量。这是「同一函数被编译器重复展开」的机器码指纹，**不是**三份手写同构代码。

> ⚠️ 更正本文档早前「疑为同一辅助函数的三份复制」的表述：当时依据只是长度相同
> + 调用特征相同；本轮字节级归一化比对才是定论。归一化脚本本身也踩过一次坑
> ——**按字节流扫 `0xE8` 会把 `mov ecx,0xabe890` 立即数里的 `e8` 误判成 call**，
> 必须借 capstone 的指令边界定位。

### `0x59D480` —— 距离用 **float** 而非 double（精度降级点）

```
dx = p1.x - p2.x ; dy = p1.y - p2.y
s  = sqrt(dx*dx + dy*dy)      // 0x4cac40
fstp dword ptr [esp+0x18]      // ★ 存成 32 位 float，不是 double
j = Random() * [0x7ED898](1/2³²) * [0x7ED768](10.0f)
  + [0x7ED764](0.5f) * arg
  - [0x7ED76c](0.02f) * (double)s
```

三处细节：

1. **`fstp dword`** —— 距离被窄化成 float 存回，`0x5A2ED0` 三兄弟存的是
   `fstp qword`。同一套算法里两种精度并存，`0x59D480` 是降级的那份。
2. 三个 float 常量实锤：`0x7ED768`=10.0f、`0x7ED764`=0.5f、
   `0x7ED76C`=0.02f（字节 `0x0AD7A33C`）。
3. `ret 0xc` = 3 个栈参、无 `this`，是自由函数（`0x5A1190` 是 4 参 `ret 0x10`）。

### `0x5A1190` —— atan2 象限归一化 + 角度抖动

```
dx = p2.x - p1.x ; dy = p2.y - p1.y
if (dx == 0) → 直接返回 π/2 基准（[0x7E2820] = 1.5707963267948966）
else         → r = 0x4cade0( −(double)dy / dx )
               if (dx < 0) r += π          // [0x7E44D0] = 3.141592653589793
r = |r − arg|
r = r mod 2π                                 // [0x7E3CC0] = 6.283185307179586
if (r ≥ π) r = 2π − r                        // 折叠到 [0, π]
return Random()*[0x7ED898]*[0x7ED790](2.0) + [0x7ED798](1.5) * r
```

**这一族里唯一处理角度的函数。** 判定依据有二：① 三个常量精确等于
π/2、π、2π（全部读字节实锤）；② 「dx<0 加 π → 取绝对值 → mod 2π →
超过 π 取 2π−r」正是 atan2 的标准象限归一化序列。

⚠️ **更正**：本文档早前把 `0x4cade0` 直接标为「atan2」是**错的**。
反汇编其全部 66 字节后确认它是**单参查表数学函数**：

```
fld qword [esp+4]                        ; 取参
fst dword [esp+4]
fdiv dword [0x8650b8]                    ; 按定标常数缩放
call 0x7c5f00                            ; ftol → int
cdq / xor eax,edx / sub eax,edx          ; 取绝对值
cmp eax, 0x1001                          ; 4097 —— 查表项数上界
jge  → 饱和取 [0x7E897C]
else fld dword ptr [eax*4 + 0x8610B4]     // 4097 项 float 表
fld dword [esp+4] ; fcomp [0x7E1748] ; 若 <0 则 fchs    // 恢复符号
ret
```

即 `0x4cade0` = **4097 项 LUT + 符号恢复**（`atan` 的表驱动实现形态）。
atan2 的**象限处理在调用方 `0x5A1190` 里**，不在被调函数里。同理
`0x4cac40`（110 B、280 callers/170 callees）实测为「负数检查 +
`0x8650BC` 指数查表 + 位操作」的 MSVC6 `sqrt` 形态，两个调用方都传
`dx²+dy²`（恒非负）。

### 「随机抽 work 格子」四件套：四级递增严格度（同一算法家族的衍生版本）

`0x58BE20` / `0x58C320` / `0x58C4A0` / `0x58C5A0` 是同一算法的**四级递增严格度**
版本，全部走同一条取数路径：

```
side = [0x89C2DC];  total = side*side;  hi = total-1
loop:
  v = _ftol( Random() * total * [0x7ED898] )   // 0x7C5F00 = ftol
  if (v > hi) goto loop                        // 拒绝采样
  p = [0xABED10] + v*0x50
  ...逐级追加的谓词...
```

四级差异（实测逐条反汇编）：

| 地址 | 长度 | 追加谓词 | 失败出口 |
|---|---|---|---|
| `0x58BE20` | 126 B | `(x,y) != (0,0)` | 继续重抽（无限） |
| `0x58C320` | 142 B | + `p->[0x38] == this->[8]` | 继续重抽（无限） |
| `0x58C4A0` | 231 B | + `p->[0x44] != 0` + `FUN_00486380(GetCellAt(...))` | **100 次上限后返回 (0,0)** |
| `0x58C5A0` | 259 B | 换谓词：`0x56D230(Instance, cell+0x24, 0) == arg2` + `FUN_00486380` + (`arg3 == -1` 时跳过 `[0x38]` 比对) | **100 次上限后返回 (0,0)** |

要点：

1. **后两级有 100 次重抽上限**（`cmp ebx, 0x64` / `cmp eax, 0x64`），超出返回
   `(0,0)`；前两级是无限重抽——即同一算法在「死循环风险」上分成两派。
2. **后两级会用 `rep movsd`（`ecx=0x14` = 20 dword = 0x50 字节）把命中记录
   整块拷进 `work[0]`**（`mov edi, ebp`，`ebp` 初值为 `[0xABED10]`）。
   这是**对 work 数组第 0 项的写入副作用**——失败路径上 `work[0]` 已被污染成
   最后一个候选。若复刻这四个函数必须连带复刻这个副作用。
3. `0x56D230` 经 `functions.tsv` 记为 `MapClass::GetMovementZoneType`，
   `symbol_source=USER_DEFINED`（**推断名，非本 exe 实锤**）。

### `0x5A6920` / `0x5A8720` —— 中立阵营平民载具布置（孪生对，差异只有「校车 vs 轿车」）

这两个是同一函数的两份改写（`0x5A8720` 与 `0x5A6920` 相隔 `0x1E00`，
结构逐指令同形，仅四个立即数与一张类型表不同）：

```
mov ecx, 0x82BA08          ; ← 字符串 "Neutral"
call 0x5117D0              ; 按名查规则类
mov ecx, eax / call 0x502D30

外层：n = _ftol( Random() * [外层系数] + 1.0 )   ; 拒绝 n > 上限
      while (i < n) {
内层：  t = _ftol( Random() * [内层系数] )        ; 拒绝 t > 上限-1
        if (t <= 2) {
          push 0x6F0 ; call 0x7C8E17            ; operator_new，1776 字节
          ecx = [t*4 + 类型表]                  ; 取载具类型名字符串
          ...造对象...
        }
        i++
      }
```

**四个系数常量实锤（全部是 `n/2^32`，读字节验证）**：

| 常量 | 值 | 用途 | 推出范围 |
|---|---|---|---|
| `0x7EDAB0` | 5/2³² | `0x5A6920` 外层 | `+1.0` 后取 1..5 |
| `0x7EDAF8` | 7/2³² | `0x5A6920` 内层 | 无偏移，取 0..6 |
| `0x7EDA38` | 4/2³² | `0x5A8720` 外层 | `+1.0` 后取 1..4 |
| `0x7EDA40` | 6/2³² | `0x5A8720` 内层 | 无偏移，取 0..5 |

`0x7E1718` = 1.0（外层的 `+1.0` 加数，与 GetPowerPercentage 共用同一常量）。

**两张类型表读出的字符串（本轮新读，之前完全未取证）**：

| 下标 | `0x5A6920` 表 @`0x82B180`（7 项） | `0x5A8720` 表 @`0x82B240`（6 项） |
|---|---|---|
| 0 | `CIV1` | `CIV1` |
| 1 | `CIV2` | `CIV2` |
| 2 | `CIV3` | `CIV3` |
| 3 | `PICK` | `PICK` |
| 4 | `WINI` | `WINI` |
| 5 | **`BUS`** | **`CAR`** |
| 6 | `CAR` | （无第 7 项） |

两表**不共享前缀**（第 5 项起分叉）：`0x5A6920` 的候选集含校车不含轿车，
`0x5A8720` 反之。其余 5 项（三种平民车 + 皮卡 + 房车）完全相同。

> **这一节解掉了本文档原先挂着的一条未确认项**——「`0x5A6920`/`0x5A8720`
> 为何出现玩法函数（寻路/开火）」。答案是：**没有矛盾**。这两个函数造的是
> **真实的游戏载具对象**（中立阵营的平民车/校车/轿车），载具对象当然带寻路
> 与开火判定方法——`AStarAttempt`/`GetFireError` 被调用是对象的正常方法调用，
> 与「地图生成为何能调玩法函数」无关。

⚠️ 保留边界：造对象之后如何落格、如何设朝向、`0x502D30` 的返回值如何参与，
本轮未逐条取。

### 编排树深处：`0x5A82E0` / `0x5A89D0` / `0x5A8F00`（2026-10-13 补取证）

这三个是编排树的深层节点（`0x5A80B0` 尾部按固定顺序调 `0x5A89D0`→`0x5A82E0`→
`0x5A8720`，见上节）。本轮反汇编后**三个都与已登记/已实锤的叶子相连**，
进一步证明这套废弃方案与活代码同根。

**`0x5A82E0` —— 调 `0x5657A0`（已登记的 GetCellAt），迭代一张邻接载具表的表**

干净 prologue（`sub esp,0x90` + push 四寄存器）。骨架：

```
n = _ftol( Random()*[0x7EDAB0](5/2³²) + [0x7E48E0] )   // 拒绝 n > 12
cell = FUN_005657A0(MapClass::Instance, arg)            // ★ 调已登记的 GetCellAt
v   = movsx byte [cell + 0x11B]                          // 读格子的 0x11B 字节字段
...
FUN_005AD6F0(...)                                        // 与 0x5A6510 同用一个辅助
mov esi, 0x82B1B0                                        // 迭代表起点
loop: ... cmp esi, 0x82B240 ...                          // 表终点
```

要点：**它调 `0x5657A0`（GetCellAt）**——这套废弃方案用的坐标→格查表，与
活代码、与我今天在 frontier 台账登记的 `0x5657A0` 是**同一个函数**。
迭代的表 `0x82B1B0..0x82B240` 紧邻 `0x5A6920`/`0x5A8720` 的载具类型表
（`0x82B180`/`0x82B240`）——死代码方案的类型表区是连片排布的。⚠️ partial：
`cell->[0x11B]` 字段语义、迭代表每项的含义、`0x5AD6F0` 的作用未实锤。

**`0x5A89D0` —— 巨型栈帧 + 1024 条记录初始化 + timeGetTime**

```
mov eax, 0x6058 / call 0x7CA650    ; __chkstk —— ★ 0x6058(24664) 字节巨型栈帧
lea esi, [esp+0x68] / mov edi, 0x400   ; 1024
loop: call 0x5A99B0 / add esi,0x14 / dec edi / jne   ; 初始化 1024 条 × 0x14 字节
...
n = _ftol( Random()*[0x7EDB28] )        ; 拒绝 n > 10
... idiv 11 取模 ...                     ; cdq/idiv ecx(=0xB)
call dword [0x7E1530]                   ; ★ timeGetTime（batch 060 已实锤槽位）
```

要点：① 0x6058 的栈帧 + 1024 条 0x14 字节记录 = 一个**本地大工作数组**
（疑似全图 512×512 的某种标记/距离场，1024≈图块数）；② 调 `timeGetTime`
——废弃方案居然带**计时**，疑似带超时上限的重试循环（试到时间耗尽就放弃）。
⚠️ partial：0x5A99B0/0x5A7D00 未取证，数组的具体语义未实锤。

**`0x5A8F00` —— 浮点计算 + 调活函数 `0x5980C0`（MapGen 活代码）**

```
cmp arg1, 1 / jle ...                ; arg1<=1 走捷径
; 设两个常量：[esp+0x3C]=0x3FE00000(=0.5) / [esp+0x34]=0x40000000(=2.0)
fld [0x7E48F0] / fcomp ...           ; 浮点比较
call 0x5980C0                         ; ★ 活 MapGen 函数（11 个外部调用者）
fmul 0.5 / fadd 2.0 / fcom 2.0        ; 值域钳制
call 0x7C5F00                         ; ftol
mov ecx, [eax*4 + 0x82B530] / mov ebp, [eax*4 + 0x82B5B0]   ; 两张表
cmp edi, 2 / jne ...                  ; 仅 edi==2 分支调 Random
```

要点：① 调 `0x5980C0`——**活的 MapGen 函数**，即废弃方案的这一步与活代码
**共享同一个子过程**（这正是「同源而非 TS 时代残留」的又一证据）；② 设
`0.5`/`2.0` 常量做值域钳制（`x*0.5 + 2.0`，把某个值压进 [2.0, ...]）；
③ 两张相邻表 `0x82B530`/`0x82B5B0`（差 0x80=32 项）。⚠️ partial：clamp
的确切语义、两张表的内容、edi 的含义未实锤。

### 编排树更深：`0x5A6D80` / `0x5A7070` / `0x5A78D0`（2026-10-13 补取证）

**`0x5A6D80` 与 `0x5A7070` —— 方向相关初始化（孪生对，0x5A5B50 各调 2 次）**

两者逐指令同形（仅栈帧大小 `0x28` vs `0x34` 与一处局部保存不同）：

```
edx = arg3
flag = (edx == 4)                ; sete
if (edx == 2) { 方向步长 = (1, 3)；偏移 = (-3, 6) }
else          { 方向步长 = (3, 1)；偏移 = (-3, 6) }   ; 主干取负一 -3
```

即「按方向参数选步长向量」的查表型初始化。`0x5A5B50` 把这对各调两次，
正是「对四个方向各初始化一次」的展开形态（MSVC 把方向循环展开）。⚠️ partial：
步长向量作用到的目标结构、-3/6 偏移的几何含义未实锤（疑似菱形邻域偏移）。

**`0x5A78D0` —— 构建参数块（0x5A5020 尾部编排调用之一）**

`sub esp,0x94` 大帧 + 往本地结构连续填 `6/4/2/0` 一串常量
（`mov [esp+0x58],6 / [esp+0x5c],4 / [esp+0x70],6 / [esp+0x80],4 / [esp+0x6c],6 …`），
是典型的「调用前打包参数结构」形态。⚠️ partial：参数块的字段含义与
接收它的下游函数未实锤。

> 阶段①至此：编排树的两个根（0x5A5020/0x5A80B0）+ 全部一级子节点
> （0x5A5360/0x5A5B50/0x5A6510/0x5A6920/0x5A78D0 与 0x5A89D0/0x5A82E0/
> 0x5A8720）+ 核心谓词（0x5A6C10/0x5A7250）+ 工具（0x5A6BA0/0x5A5AE0）
> 全部取过证，**且三个深层节点与已登记的活代码叶子（GetCellAt、timeGetTime、
> 0x5980C0）相连**。剩余未取证的只剩 `0x5A76E0` 与各函数的字段级语义。

### `0x5A76E0` —— 「矩形完整落在菱形区域内」谓词（最后一个死代码函数）

干净 prologue（`sub esp,0xC` + push 四寄存器）。读入参结构
`{int16 x, y; int32 w, h}`（`this->[0]`=坐标对、`this->[8]`=宽、
`this->[0xC]`=高），对**矩形的每个角**做同一组菱形边界检查：

```
x = this->[0].x ; y = this->[0].y ; w = this->[8] ; h = this->[0xC]
对每个角 (cx, cy) ∈ {(x,y), (x+w-1,y), (x,y+h-1), ...}:
    if (cx+cy >  W)      exit      // [0xABED04] = W
    if (cx-cy >= W)      exit
    if (cy-cx >= W)      exit
    if (cx+cy >  W+2H)   exit      // [0xABED08] = W+2H
```

`lea edx,[edx+ecx-1]` / `lea edx,[edx+edi-1]` 是「角坐标 = 角点 + 宽/高 - 1」
的逐角推进。判定依据：① `[0xABED04]`/`[0xABED08]` 已在 batch 060/061 实锤为
W 与 W+2H；② 这组 `x+y`/`x-y`/`y-x` 与双边界比较，与 `0x5A7250`（单点菱形
检查）是**同一组菱形谓词**——`0x5A76E0` 是它的**矩形角版本**（整个矩形
四角落进菱形才算合法）。

> **阶段①取证至此闭合**：编排树两个根 + 全部一级子节点 + 核心谓词
> （0x5A6C10/0x5A7250/0x5A76E0）+ 工具（0x5A6BA0/0x5A5AE0/0x5A6D80/0x5A7070）
> 全部取过证。剩余仅是各函数的字段级语义（如 0x5A6C10 的 [0xA8ED2C] 表写入点）。

- `0x59A63B-0x5A8F00` 后段 11 个：`0x59D480` `0x5A1190` `0x5A1E10` `0x5A2ED0`

## TU 归属铁证：MapGen.cpp 自身含零调用函数

`0x597380` 同时满足两个独立证明：

1. **归属 MapGen.cpp**：函数体内 `0x5973EC` 处为调试宏
   `push 0xF5E`（行号 3934）+ `push 0x82BA48`（MapGen.cpp 源文件字符串 VA，
   与 `scan_source_macros` 报告的 `str@0x82ba48` 一致）。
2. **零引用**：`xref_abs.py` 与 `xref_rel32.py` **各报 0 处**。

且 MapGen.cpp 断言区间（20307 字节）内共有 **5 个**零调用函数：
`0x595740`(404B) `0x5958E0`(725B) `0x596300`(2385B) `0x597380`(172B) `0x598000`(39B)。

> **结论：「MapGen.cpp 自身含有零调用函数」是已证事实，不再是推断。**

这使"死代码零散分布"这一现象获得解释：链接器未开 `/OPT:REF`，同一个 TU
内部就会有从未被调用的成员函数。

`scan_source_macros.py` 实测 36 个 TU，`MapGen.cpp` 的断言宏只覆盖
**`0x5956E7-0x59A63A`**（21 处，行 3934-6746）。而这 22 个函数散布在
**`0x58BE20-0x5A8F00`**，明显溢出该区间。断言宏只出现在有 `assert` 的代码处，
所以「落在宏区间外」**不能**推出「不是 MapGen.cpp」。

**2026-10-13 取证**——子树根 `0x5A5020` 的反汇编调用序列里有：

```
005a50c0  call 0x598030     ← 活函数（10 个外部调用者）
005a52d4  call 0x5980c0     ← 活函数（11 个外部调用者）
```

两个都在 MapGen.cpp 断言区间 `0x5956E7-0x59A63A` 内。加上死代码与活代码共用
同一套全局（`Randomizer @0xABE890`、work 数组 `@0xABED10`、边长 `@0x89C2DC`）
和同一套 `scaled_random` 惯用法，且物理相邻——**强证据指向同属 MapGen.cpp
（YR 自己的代码层），而非 TS 时代跨时代残留**。

**断言行号分布解释了区间外溢**（`scan_source_macros.py MapGen` 明细）：
MapGen.cpp 的 21 处断言行号为 3934（5 处，分别在 `0x5956E7`/`0x595713`/
`0x596620`/`0x596802`/`0x5973EC`）、4883–4949、5433、5572–5590、6746，
行号跨度大且分布稀疏。这说明断言只落在**源文件中后段**——3934 行之前与
6746 行之后的代码都不带断言。因此死代码落在宏区间之外（`0x58BE20-0x5A8F00`
横跨 `MapGen.cpp` 断言区的前后两侧）**与「同属 MapGen.cpp」并不矛盾**，
它们很可能就是该 TU 里无断言的那部分代码。

⚠️ **仍是推断而非铁证**：调用关系 + 全局共用 + 物理相邻 + 断言行号分布
都不能单独证明 TU 归属。要钉死需：① 对 `0x598030`/`0x5980C0` 实锤其确在
MapGen.cpp；② 或找该 exe 的 `.obj`/COMDAT 边界证据。**未做**。

## 两个零引用根：编排树结构

`0x5A5020`（827 B）与 `0x5A80B0`（546 B）是两个零引用根，二者都直接触碰
MapGen/RMG 的三样核心设施：

| 设施 | 用途 | `0x5A5020` | `0x5A80B0` |
|---|---|---|---|
| `[0x89C2DC]` | 工作数组边长 | 读 | 读 3 次 |
| `[0xABED10]` | 每格 0x50 字节工作记录 | 索引 | mov + 读 |
| `Randomizer @0xABE890` | 引擎随机源 | 调 | mov + 调 |

`0x5A80B0` 另调用 `0x5A7250` 与 `MapClass::IsWithinUsableArea`(0x578460)，
并在函数尾部**按固定顺序**再调用另外三个死代码子树根：
`0x5A89D0` → `0x5A82E0` → `0x5A8720`。

`0x5A5020` 的尾部同样以固定顺序调用 `0x5A5360` → `0x5A5B50` → `0x5A6510`
→ `0x5A6920` → `0x5A78D0`。

> **这批函数彼此按固定顺序互相调用、形成一棵有序的编排树**——它们不是零散
> 残留，而是**一整套设计完成但从未被接线的算法**。结合它们与活代码共用同一
> 套全局与惯用法，读法是：YR 自己在 MapGen.cpp 里实现了一套完整的
> 「遭遇战实体布置」方案，最终决定启用的是另一套（那 104 个活取数点所属的
> 方案），这套就被链接器留了下来。

⚠️ 「最终启用了另一套」这一读法是**推断**：本 exe 内没有留下「哪套被启用」
的直接痕迹，零引用只能证明静态不可达。

### `0x5A6BA0` —— 锚点邻域格子合法性扫描器（零取数点）

```
X = *(int16*)(ecx);  Y = *(int16*)(ecx+2)
for y in [Y-7, Y+7):            ; 外层
  for x in [X-7, X+7):          ; 内层
    if (FUN_004863d0( GetCellAt(MapClass::Instance@0x87F7E8, x, y) ))
        return false;           ; al=0  —— 邻域内有可用格
return true;                    ; al=1  —— 邻域全不可用
```

**不调用 `Randomizer`、零取数点**（实测 110 字节，仅 2 个 call：`GetCellAt`
与 `FUN_004863D0`）。

因此它不是布置逻辑本身，而是布置逻辑要用的**探测/校验工具**：在给定锚点
附近（±7 格）找一块可用地。

这解释了两件事：① 它零调用但落在死代码区——工具函数随主算法一起被废弃；
② 它**被原 22 个清单漏掉**——`rng-ledger` §二 按「取数点分组」筛选，
不消耗随机数的辅助函数根本不会进入清单。这是原筛选口径的系统性盲区，
不止影响 `0x5A6BA0`/`0x5A1E10`/`0x5A3A60` 三个。

### `0x5A1E10` —— MapType 3/4 门禁（与活代码平行的一套编排）

```
if (this->[0x3c] == 3 || this->[0x3c] == 4) {
    FUN_0058ebc0(this);
    FUN_0058ef10(this);
    FUN_005a19e0(this);
    RepaintAll(MapClass::Instance, /*owner=*/0, /*?=*/-1);   // 0x578E60
    FUN_005a17f0(this);
}
```

实测 56 字节，**零取数点**。

关键：`0x578E60` 带 `(-1, 0)` 实参——这正是
[stage-making-regions.md](stage-making-regions.md) 记录的 `RepaintAll` 实锤
调用形态（调用点 `0x598D73` 为 `push -1`）。故这是一条 **MapType 3/4 门禁**。

> **这是本轮最重要的发现**：死代码区里躺着一份**与活代码 MapType 3/4 分支
> 平行的一套编排**。它直接回答了「它们被什么替代了」——不是被另一套地形
> 方案替代，而是被**另一套 MapType 3/4 编排**替代。原版作者为同一分支写过
> 两版，最终保留一版、链接器把另一版留下。

⚠️ 「保留了一版」是**推断**：零引用只证明静态不可达，exe 内没有痕迹表明
哪一版曾被调用。

### `0x5A3A60` —— 全图扫描 + `Y*side+X` 线性索引（零取数点）

```
MapClass::CellIterator_Reset(0x578350)
loop {
    cell = MapClass::CellIterator_Next(0x578290);
    work = [0xabed10] + index * side;      // imul eax, [0x89c2dc]
    ...
}
MapClass::CellIterator_Next(0x578290)     // 第二轮遍历
```

实测 125 字节，零取数点。`imul eax, [0x89C2dc]`（× 边长）即 RMG 工作数组
的 `Y*side + X` 线性索引约定——与活代码同一套寻址。

### `0x5A5AE0` —— 切比雪夫距离 + 随机抖动（放置偏移取点）

```
dx = p1.x - p2.x ; dy = p1.y - p2.y      ; 两侧都是 movsx int16
adx = abs(dx) ; ady = abs(dy)            ; cdq/xor/sub 无分支绝对值惯用法
base = max(adx, ady)                     ; 切比雪夫距离，非欧氏
jitter = (double)(uint32)Random() * [0x7ED818] * [0x7ED898]
return base + jitter;
```

实测 107 字节，**1 个取数点**（`Randomizer::Random`）。

要点：
- 两个入参按 `movsx word ptr` 读——是**格子坐标对**（各 2 个 int16），
  不是对象指针；
- 取 `max(|dx|,|dy|)` 而非 `sqrt(dx²+dy²)`——切比雪夫距离是**格子世界**
  的自然度量；
- `[0x7ED818]` 与 `[0x7ED898]` 两个常量连乘，与活代码的 `scaled_random`
  惯用法同款（后者是 `1/4294967295.0`）。

这是放置实体时"在两个锚点之间取一个偏移格"的写法，与 `0x5A6BA0`
（邻域合法性扫描）配套：先按切比雪夫距离取偏移，再用扫描器验证落点。

### `0x5A7250` —— 坐标组合的边界校验（被调 7 次）

读入参结构 `{int16 a; int16 b; int32 c}`，把下列组合逐一与全局
`[0xABED04]`（下界侧）和 `[0xABED08]`（上界侧）比界，任一越界即走 0x5A742A
的失败出口：

```
a + b
a - b
b - a
(a + c - 1) + b
```

⚠️ 两点值得注意：① 四个组合都是**两个坐标的加减**（外加 `c` 参与的第三项），
这是「矩形/区间合法性」的标准写法；② `[0xABED04]` 与 `[0xABED08]` 与 work
数组基址 `[0xABED10]` **地址相邻**（相差 4 和 8），是同一结构里的两个
**尺寸字段**（`[0xABED04]`=W，写入点 `0x566306`；`[0xABED08]`=W+2H，
写入点 `0x566317`，2026-10-13 已实锤）。
**2026-10-14 余段已全段读完闭合**（0x5A7250 起 420+ 指令，此前只读到比界部分）：
整体是**菱形域矩形合法性校验 + cell 谓词链**——四角逐一过菱形边界判定
（`X+Y ∈ [W+1, W+2H]`、`|X-Y| < W`），再经 `GetCellAt`(0x5657A0) 与
`0x4866D0`/`0x4866F0`/`0x486380`/`0x486650`/`0x486670` 谓词链逐步判定，
**双出口**：`0x5A741E`（al=1 通过）/ `0x5A742A`（al=0 失败，即前文比界
失败出口）。

## 2026-10-15 续：`0x5A82E0` —— 批量放置对象（唯一 `new(0x720)` 的死代码函数）

**全段实测 0x5A82E0–0x5A8705（约 1062 B）**，`disasm.py` 四段拼读，出口
`0x5A86EB` → `0x5A8705 ret`。机器码分七段：

1. **类型拒绝采样（13 值）**：`mov ecx,0xABE890` + `call 0x65C780`
   （`Randomizer::Random`）→ `fild qword [esp+0x58]`（**32 位随机数按无符号读**）
   → `fmul [0x7EDAB0]` → `fadd [0x7E48E0]` → `call 0x7C5F00`（`_ftol`）
   → `cmp eax,0xC / ja 0x5A82EC`——**上界 12，拒绝采样**（13 个类型）。
2. **取单元格**：`push`栈参1 + `mov ecx,0x87F7E8`（`MapClass::Instance`）+
   `call 0x5657A0`（`GetCellAt`）→ `movsx eax,byte [eax+0x11B]`
   （**有符号字节读**，非 `movzx`）。
3. **双档位门**：`cmp [esi+0x38],0` → 非零走 `0x23(35)`，为零走 `0xF(15)`；
   第二档同时是采样下界（`lo`）。
4. **36 项类型表过滤**：`mov esi,0x82B1B0` … `cmp esi,0x82B240 / jl`——步进 4
   （**36 项**，与文档前述"连片排布的类型表区"同一区）；过滤走
   **虚表槽 `+8`**：`call dword [edx+8]`，返回 `al` 决定是否收进候选数组；
   另用 `0x7E5BC4` 虚表 + `call 0x5AD6F0` 构造本地容器。
5. **区间拒绝采样取索引**：`fild`(上限−下界+1) → `fstp`；`fild`(下界) → `fstp`；
   `Random` → `fmul [esp+0x60]`（区间长）→ `fmul [0x7ED898]`（**×2⁻³² 比例**）
   → `fadd [esp+0x40]`（下界）→ `_ftol` → `cmp eax,esi / ja` **拒绝采样**。
6. **对象构造**：`call 0x5117D0` / `0x502D30` 取表对象 →
   `push 0x720` + `call 0x7C8E17`（**`operator new(1824)`**）→
   `call 0x43B740`（构造，参数 = `[0xA83C6C][idx*4]` 表项 + 上述表对象）。
   ⚠️ **`0x720=1824 B` 是死代码区最大单对象分配**。
7. **60 次放置尝试**：`cmp [esp+0x40],0x3C / jge`（**上限 0x3C=60**）→
   两次 0..14 拒绝采样（`fmul [0x7EDB18]`、`cmp ≤ 0xE`）→ `lea ecx,[esi-7]` /
   `add eax,-7`（**归中到 ±7 偏移**）→ 基准坐标 `[edi]`/`[edi+2]` 各加偏移
   → `call [edx+0x90]`（子对象虚表槽 0x90 取结果）→
   成对 `0x7FFF` 哨兵判定（`cmp ax,0x7FFF` + `cmp [ebp+2],ax`）→
   `GetCellAt(0x5657A0)` → 安装判定链：`[esi+0xE4]==0`（无对象）+
   `call 0x486380` 谓词 + `movsx byte [esi+0x11B]` **与目标类型相等** +
   `[esi+0xEC]!=3` + `call 0x578540`（带 push 1）→ 全过则坐标
   `×256 + 0x80`（**等距→像素**）经 **虚表槽 0xD8** 提交；
   失败/容量满则 **虚表槽 0x20** 释放对象（`push 1` + `call [eax+0x20]`）。
   数组用「前移紧缩」回收空位（`mov [ecx+eax*4-4],edx` 循环）并 `dec` 容量。

**语义（推断名）**：**废弃方案里的「按随机类型批量放置对象」函数**——选类型
（0..12）→ 按 36 项类型表 + 谓词过滤建候选 → 区间采样取一项 →
`new(1824)` 构造 → 绕基准格 ±7 范围 60 次尝试落位，落位前过「空格 / 谓词 /

⚠️ partial：函数精确名、`this+0x38` 语义（档位开关推断）、`0x82B1B0` 表项结构、
`0x486380`/`0x578540`/`0x43B740` 函数名、虚表槽 `+8`/`0x90`/`0xD8`/`0x20` 方法名。
**本条与活代码无任何同签名孪生**（孪生签名分析已证），故仍属"独一份、从没被接线"

## 2026-10-15 续：`0x5A89D0` —— 批量放置主循环（1024 环形槽，1320 B）

**全段实测 `0x5A89D0`–`0x5A8EF8`**（`ret 4` 后 7 个 `nop` 垫到 `0x5A8F00`，
`disasm.py` 四段拼读）。开头的 `mov eax,0x6058` + `call 0x7CA650` 是
**24664 字节栈帧探测**（`__chkstk` 惯用法）——死代码区最大栈帧。

**两个 1024 槽并行数组**（同一栈帧）：
- `[esp+0x68]` 起：**1024 × 0x14 = 20 字节**的放置项数组；开段用
  `lea esi,[esp+0x68]` / `mov edi,0x400` / `call 0x5A99B0` / `add esi,0x14` /
  `dec edi` 逐项**构造**（`0x5A99B0` 是项构造器）。
- `[esp+0x5068]` 起：1024 个 dword 的辅助数组（存 `call [0x7E1530]` 的返回值）。

**主循环（`0x5A8A0A` 起）分七步：**

1. **11 值类型拒绝采样**：`Random()` → `fild qword` → `fmul [0x7EDB28]`
   → `_ftol`（`0x7C5F00`）→ `cmp edi,0xA / ja 0x5A8A0A`——**上界 10（11 个类型）**。
2. **11 次表内探测**：`lea eax,[edi+ebx]` + `mov ecx,0xB` + `cdq` + `idiv ecx`
   → **`(采样值 + 计数器) % 11`**（余数）→ `add esi,[0xABAD20]`（**11 项全局
   类型表**）→ `call 0x5A7D00` 判定；`inc ebx / cmp ebx,0xB / jl` 最多 11 次，
   **全失败则 `xor al,al / ret 4`（返回 0）**。
3. **入队**：成功项以 `rep movsd` ×5（**正好 0x14 字节**）从栈临时区拷进
   `[esp+0x68] + idx*0x14`；写入位置 `inc edx / and edx,0x3ff`（**1024 环形**），
   计数 `inc eax`；随后 `cmp eax,0x3FC / jge 0x5A8E7C`——**计数 ≥1020 转"排空"
   分支**。
4. **哨兵 + 两项子处理**：当前项首 dword `cmp ecx,0xFFFF`（**0xFFFF 哨兵 = 空**）；
   第一 dword 非哨兵时 `call 0x5A7FA0`；随后 `push -1 / push -1` +
   `call 0x5A6C10`（**已登记：表派发 + 虚调用 + 坐标累加**）。
5. **LAT 类型索引映射（原位三档判定，值得单独记）**：
   `mov edx,[0xABC1D4]` → 若 `[0xABC1D4] ≤ ecx < [0xABC1D4]+0x65` 则
   `idx = ecx - [0xABC1D4]`；否则测 `[0xABBEC0]`，若
   `[0xABBEC0] ≤ ecx < [0xABBEC0]+8` 则 `idx = ecx - [0xABBEC0] + 0x65`；
   **否则 idx = 0**——即"**0x65(101) 个 LAT 号段 + 8 个特例号段**"，落空归 0。
   随后 `lea edx,[eax+eax*2]` + `mov eax,[edx*4 + 0xABE370]` → **12 字节/项的全局
   表**（`[0xABE370]`）。
6. **≥2 项时开临时数组**：`cmp eax,1 / jle 0x5A8D06`（1 项及以下跳过）→
   `lea edx,[esi+esi*4] / shl edx,2`（**计数 ×0x14**）→ `call 0x7C8E17`
   （`operator new`）→ 失败 `je 0x5A8CFA`；成功则逐项填初值：
   `mov dword [esi-8],0xFFFF` + 两次 `call 0x42D470` 取值写 `[esi-4]`/`[esi+4]`
   + `mov dword [esi],0xFFFF` + `mov dword [esi+8],-1`（**每项双 0xFFFF 哨兵 +
   尾字段 -1**），步进 0x14。
7. **定位 + 校验 + 提交**：取项内 dword 作 iso 号 → `and eax,7` / `and esi,7`
   （**取模 8 索引**）→ `mov bx,word [eax*4 + 0x89F688]` /
   `mov ax,word [eax*4 + 0x89F688 + 2]`——**`0x89F688` 即 8 方向偏移表**
   （每项 4 字节 = 两个 word，QWEN.md 记载的 CST 邻域表）→ 与基准坐标相加得
   目标格 → **`call 0x5A8F00` 两次**（下一次取点的目标）：
   - 第一次 4 栈参：`push 1 / push [edi+4] / push [edi+8] / push [esp+0x34]`
   - 第二次 4 栈参：`push 4 / push [edi-4] / push edi / push [edi+0xC]`
   两次返回 `al` 都参与判定（`test al,al / je 0x5A8DC0` 清标志字节
   `[esp+0x13]=0`；第二次成功走 `0x5A8D79`）。随后
   `call [0x7E1530]`（**导入 API**）→ 结果写 `[esp+ecx*4+0x5068]` 辅助数组 →
   环形下标 `inc eax / and eax,0x3ff` + 计数 `inc`；容量门
   `cmp [esp+0x5c],0x400 / jge` 跳过写入。

**收尾（`0x5A8DED`）**：遍历临时数组逐项 `cmp [esi-8],0xFFFF` → `call 0x5A7FA0`；
`cmp esi,0xFFFF` → `push -1 / push -1` + `call 0x5A6C10`；
`test eax,eax / je` → `push eax` + **`call 0x7C8B3D`**（batch 001 `operator delete`）；
环形计数 `inc edx / and edx,0x3ff` + `dec eax`；循环判 `jne 0x5A8AE1`。
**返回值**：`cmp [esp+0x30],1 / jle 0x5A8A65`（返回 0）→ 否则 `mov al,1 / ret 4`
——即**"本轮是否放置了 ≥2 项"**。另有一处 `0x5A8E7C` 排空分支（计数 ≥1020 时
走同一套"逐项 0x5A7FA0 + 0x5A6C10 + 释放 + 环形 dec"清理）。

**语义（推断名）**：**批量放置主循环**——在 1024 槽环形数组上反复投递放置项：
11 类型拒绝采样选类型 → 按 11 项表 `[0xABAD20]` 探 11 次找可放置项 → 项入队
（20 字节/项）→ 经 `[0xABC1D4]`/`[0xABBEC0]` 号段把 iso 号映射成 LAT 类型索引
（落空归 0）→ 取 `[0xABE370]` 12 字节表项 → 用 `0x89F688` 8 邻域表偏移定位 →
`0x5A8F00` 双向校验 → 写入环形队列并推进。

★**跨批次连接（本条价值）**：
