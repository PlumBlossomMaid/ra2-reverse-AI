================================================================================
★ 方法论发现：ranking.tsv 的扇入候选里混入了「mid-function 地址」
================================================================================
本批取 top 候选反汇编时发现两个地址**不是干净的函数入口**：

`0x4A1D10`（70 callers）——起始指令 `add dword ptr [eax], 0x4f46c333`
直接用了未初始化的 eax（无 prologue、无加载），且 `jne 0x4a1cfa` 向后跳。
这只能是某个函数**中段的地址被误当成入口**。

`0x634D40`（66 callers）——起始 `push dword ptr [ebp+4]` 用了未建立的
ebp（无 push ebp / mov ebp,esp 帧建立）。同样是中段地址。

对照之下，同区段的 `0x4A1D30`/`0x4A1D50`/`0x4A1D70` 都是干净的入口
（`mov ax, word ptr [esp+4]; lea edx,[esp+4]; push 2; push edx; call 0x4A1DE0`
的小包装函数），说明**这个区段确实有一群真实的小函数，但 0x4A1D10 不是**。

**方法论含义**：callgraph 工具在「多跳转表/中段标号」上会把非入口地址
记成 entry 并算出扇入。**后续批次取候选时，应先验证反汇编开头是干净的
prologue**（push ebp/mov ebp,esp 或 push 寄存器起手），否则「高扇入」
可能是假信号。这类 mid-function 地址**不登记**为独立条目。

0x00A8ED2C —— 按类型索引的全局对象表（79 处引用，写入点待查）
================================================================================
承接阶段①遗留（0x5A6C10 的 `[0xA8ED2C][ecx]` 派发）。`xref_abs.py` 实测
79 处引用，集中在：

- CellClass 区（0x47BFB2 / 0x47C0E5 / 0x47C0F0 / 0x47C77C / 0x47D1DC /
  0x47D347 / 0x47D59D …——与 batch 061 的 GetCellFloorHeight `0x47B3A0` 同区）
- 0x465xxx（0x46552A / 0x465D11）
- 0x54xxxx 区（0x543791 / 0x544988 / 0x544AE3 / 0x544CF4 / 0x545466 /
  0x546C32 …，0x54 是另一功能块）
- 0x56xxxx / 0x57xxxx / 0x58xxxx（MapClass 区）

即 [0xA8ED2C] 被 CellClass 与多个功能块按「类型下标」索引，是一张
**全局对象/类型注册表**（0x5A6C10 按第 1 参取表项，与本观察一致）。
⚠️ 保留边界：**写入点未定位**（xref 全是读引用，需找出是哪个函数把对象
注册进这张表）；表项的具体类型未实锤。故本条记为观察，不登记独立结论。
