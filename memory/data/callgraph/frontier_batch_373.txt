0x005BBED0 —— 尾跳 thunk（5B）（5 callers，全 5 字节读完；deps=130）
================================================================================
机器码（**全 5 字节**）：
```
005bbed0  e9 0b000000   jmp 0x5bbee0      ; ★相对跳转 = 0x5BBEE0 − (0x5BBED0+5) = 0x0B
005bbed5  90 × 11 个 nop                  ; 垫到 0x5BBEE0
```
语义：**尾跳 thunk（推断名）**——函数体只有一条 `jmp`，无栈帧、不改寄存器、
**不返回**（控制权直接交给目标）。这是链接器/编译器为「跨编译单元或跨
vtable 槽的地址稳定」生成的转发桩；`ranking.tsv` 已给出带名
`thunk_FUN_005bbee0`——**本条为该命名的机器码实锤**（`jmp` 目标地址恰好
= 0x5BBEE0，与命名一致）。
★转发目标顺读：`0x005BBEE0` = `push esi / mov esi,ecx / push edi / xor edi,edi`
→ 对 `[esi+0]`、`[esi+4]`、`[esi+8]`、`[esi+0xc]`、`[esi+0x10]` **逐个**
`mov eax,[esi+X] / cmp eax,edi / je skip / push eax / call 0x7C8B3D
（**batch 001 operator delete**）/ add esp,4 / mov [esi+X],edi`——即
**多字段逐槽释放清理（5 个字段，含 +0x10）**，非空才释放、随后清零。
⚠️ partial：宿主类、5 个字段各自的语义、为何需要 thunk（而非直接调用）。

0x00753C70 —— 常量地址 getter（6B）（5 callers，全 6 字节读完；deps=99）
================================================================================
机器码（**全 6 字节**）：
```
00753c70  mov eax, 0xb2d928   ; ★返回常量地址
00753c75  ret
```
语义：**常量地址 getter（推断名）**——`return &g_object_at_0xB2D928;`，
无参数、不访存（只搬立即数）。**这是「单例/全局对象地址出口」**：把
`0xB2D928` 这个全局对象的地址包成函数，便于后续改成惰性创建而不动调用点
（与 batch 372 的 `0x407010`/`0x407020` 是同一设计手法）。
★邻函数对照（同 call 内顺带读出）：`0x00753C80` = `sub esp,0x78 / push
ebx/ebp / mov ebx,edx / mov ebp,ecx / mov edx,[esp+0x88] / push esi/edi /
lea ecx,[esp+0x58] / call 0x5AFC20 / mov ecx,0xC …`——一个**双寄存器参
（ecx/edx）+ 大栈帧**的实函数，说明本条边界干净（6B 后即 `ret`）。
⚠️ partial：`0xB2D928` 对象类型（单例推断）、为何用函数而非直接寻址。

================================================================================
0x004026A0 / 0x004026B0 —— 虚调用转发 thunk 对（各 9B）（各 5 callers，全 9 字节读完；deps=34/34）
================================================================================
机器码（**两条各 9 字节，逐字节同构，仅位移差 4**）：
```
004026a0  mov eax, [ecx+0xD4]   ; ★this+0xD4 = 子对象指针
004026a6  jmp dword [eax+0x28]  ; ★尾跳子对象虚表槽 0x28
004026b0  mov eax, [ecx+0xD4]   ; ★同一个子对象
004026b6  jmp dword [eax+0x2C]  ; ★尾跳虚表槽 0x2C
```
语义：**虚调用转发 thunk 对（推断名）**——`__thiscall` 取 `this+0xD4` 指向的
子对象，再**尾跳**其虚表槽（前者 `+0x28`、后者 `+0x2C`），参数原样透传
（`jmp` 不改栈，故被转发的虚函数直接看到本函数的参数与返回地址）。
**这是多重继承/组合下的「成员对象方法再导出」标准形态**：外层类把对
子对象（`+0xD4`）的两个虚方法挂到自己身上，调用者不必先取子对象。
★原版怪癖（照抄）：① **用 `jmp [eax+off]` 而非 `call` + `ret`**（尾调用优化，
省一次返回——被转发方法的 `ret N` 直接返回给原始调用者，**栈参数个数由
被转发方法决定，本函数签名不可独立推断**）；② **两条同构仅位移差 4**
（编译器为连续两个导出方法各生成一份）；③ 子对象指针字段固定 `+0xD4`
（两条都用同一字段，说明是同一次布局决策）。
★邻函数对照（同 call 内顺带读出）：`0x004026C0` = `push esi / mov esi,ecx /
mov eax,[esi+0xD4] / call dword [eax+0x28] …`——**第三条同族**，但用
`call`（**非尾跳**，因为还要在本函数内继续做事），恰好反证前两条是纯转发。
★跨批次连接：虚表槽 `0x28`/`0x2C` 与 **batch 369 的 `0x004F4320`**
（其中 `call [edx+0x28]` / `call [edx+0x2C]` / `call [edx+0x30]` / `call [edx+0x5C]`）
**槽号重合**——虽作用对象不同（本条是 `this+0xD4` 子对象、batch 369 是
全局/`this`），但**同一批槽号在引擎里反复出现**，值得后续批次留意是否
同族基类接口（⚠️ 仅为槽号观察，**不作同一接口的断言**）。
⚠️ partial：宿主类与 `+0xD4` 子对象类型、槽 0x28/0x2C 方法名、被转发方法的
真实参数个数（尾跳导致本函数签名不可独立推断）。
