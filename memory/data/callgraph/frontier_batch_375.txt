0x00725C70 —— 全局对象表遍历重建（推断名，286B）（4 callers，全段读完；deps=3132）
================================================================================
机器码（要点）：
```
push ecx（腾局部）；mov eax,[0xB0F6A8]（★全局计数）；push esi；xor esi,esi
test eax,eax / jle 出口
循环 0x725C81：
  mov eax,[0xB0F69C]（★全局数组基址）；mov ecx,[eax+esi*4]（项）
  mov [esp+4],ecx（存局部）
  mov edx,[ecx] / call [edx+0x44]（★虚表槽 0x44，返回 al）
  test al,al / je 0x725D7F（不通过 → 下一个）
  mov edx,[0xB0F698]（★全局对象）/ lea eax,[esp+4] / push eax
  mov ecx,0xB0F698（★this = 全局对象）/ call [edx+0x10]（★虚表槽 0x10 → 索引或 -1）
  cmp eax,-1 / je 0x725CE1
  cmp eax,[0xB0F6A8] / jge 0x725CE1
  dec [0xB0F6A8]（计数--）
  cmp eax,ecx / jge 0x725C9A        ← ★跳回重试（重新调虚表槽 0x10）
  数组前移：mov edx,[ecx+eax*4] / mov [ecx+eax*4-4],edx …… jl → jmp 0x725C9A
  0x725CE1：push [esp+4] / mov ecx,[eax] / call [ecx+8]（★虚表槽 8）
            test eax,eax / je 0x725D80
            名字比较链 ×4：
              call 0x7CAA05（每轮对同一对象取串）→ mov ecx,0x818D60 /
              call 0x7C8AD3 → test/jne 命中
              再 0x842D80、0x825508、0x817B90（共 4 个常量串）
  0x725D63（命中任一）：mov byte [eax+0x90],1（★置标志）
  0x725D6E：mov ecx,[esp+4] / test / je / mov edx,[ecx] / push 1 /
            call [edx+0x20]（★虚表槽 0x20 带参 1 —— 自删除）
  0x725D7F：inc esi
  0x725D80：cmp esi,[0xB0F6A8] / jl 0x725C81
出口：pop esi / pop ecx / ret
```
语义：**全局对象表遍历重建（推断名）**——按 `[0xB0F6A8]` 计数遍历 `[0xB0F69C]`
对象数组：① 每项先过**虚表槽 0x44** 判据；② 通过后调全局对象 `[0xB0F698]` 的
**虚表槽 0x10** 求索引，索引有效则**从数组里移除该项（元素前移 + 计数--）并跳回
重试**（同一项被反复投喂直到返回 -1/越界）；③ 再调**虚表槽 8**，把结果串与
**4 个常量串**（0x818D60 / 0x842D80 / 0x825508 / 0x817B90）逐一比较，命中则
`byte [obj+0x90] = 1`；④ 最后经**虚表槽 0x20 `push 1`** 自删除。
★原版怪癖（照抄）：① **移除后跳回重试**（`jge 0x725C9A` 跳回**虚表槽 0x10 调用
点**而非循环头——同一项被当作新的一项重复投喂）；② **数组前移用 `inc eax` 后
`[ecx+eax*4-4]` 的写法**（`+eax*4-4` 抵消，等价于从 idx 起逐个覆写）；③ 命中
后**先置标志再自删除**（`+0x90` 置 1 后立刻 delete）。
★跨批次连接：`[0xB0F69C]`/`[0xB0F6A8]`（全局数组 + 计数）与 `[0xB0F698]`
（全局对象）为本条新登记的**全局三元组**；4 个常量串地址已登记待读
（0x818D60 / 0x842D80 / 0x825508 / 0x817B90——⚠️ 内容未读，**不猜语义**）。
⚠️ partial：宿主/全局对象类型、虚表槽 0x44/0x10/8/0x20 方法名、4 个常量串内容、
`+0x90` 标志语义、"移除后重试"的业务意图。

0x006D6AD0 —— 单元格 +0x11C 字节 getter（推断名，28B，ret 4）（4 callers，全 0x1C=28B 读完；deps=1970）

```

006d6ad9  push eax
006d6ada  call 0x565730           ; ★cell 访问器（与 0x5657A0 GetCellAt 同族）

★跨批次连接：`IsoCell` 布局锚点群再 +1：`+0x11B`（死代码区 `movsx` 有符号读，

```

0071dca5  sub esp,0x26C           ; ★大帧

旧缓冲**（`operator delete` 后清 `+0xA4`）并清标志 `+0xA8`；④ 收尾**双析构**
（虚表 `0x7E16B0` → 0x43AE50；虚表 `0x7E1668` → 0x431B80）。
★跨批次连接（**本条集中命中**）：
- **`0x7C9FF0`（batch 004 —— `assemble_path`）**：本条为**五参调用现场**，且第 5 参
  形态（`0x7E1BC6 + idx*112`）与 **batch 367 的 `0x6B5490`** 记录的同款写法一致

- **`0x4739F0`（batch 063 —— CCFileClass 构造）** + **`0x4A3890`（batch 139 ——

- **`0x7C8B3D`（batch 001 —— `operator delete`）**：释放旧缓冲。
- **双析构虚表对 `0x7E16B0`/0x43AE50 + `0x7E1668`/0x431B80 与 batch 370 的
  `0x679D90` 完全同款**——**两条独立的「临时文件对象析构」链路同模板**，可据此
  推断是同一个 CCFileClass 家族的两个不同用途实例。
- 新登记全局：`[0xA8E31C]`（对象数组）/`[0xA8E328]`（计数）/`0x7E1BC6`（路径串表
  基址）；项字段 `+0x22C`（装载门控）/`+0xA4`（缓冲指针）/`+0xA8`（标志）。
★原版怪癖（照抄）：① **`this*112` 的步长寻址**（`lea ecx,[ebp*8]; sub ecx,ebp;

⚠️ partial：`[0xA8E31C]` 数组元素类型、`0x7E1BC6` 路径串表内容、`+0x22C`/`+0xA4`/

（batch 375 说明：C++ 模型决策）
================================================================================
本批三函数**不新增 C++ 模型**，理由：
① 0x00725C70（全局对象表遍历重建 286B）——**语义依赖 4 个全局（数组/计数/对象）
与 4 个常量串内容**，其中串内容本轮未读；重写需先补齐这些外部锚点，故不落模型。
② 0x006D6AD0（cell +0x11C getter 28B）——一行取值，脱离 IsoCell 布局无意义；
其价值是**登记 `+0x11C` 的零扩展读**（与 `+0x11B` 的有符号读成对）。
③ 0x0071DCA0（逐项文件装载 220B）——**本条价值全部在调用链与布局锚点上**（三个
已登记批函数 + 同款双析构），属"接线证据"而非可独立单测的算法切片。
本批无产品代码改动，ctest 维持 **43/43 全绿**（batch 372 已实跑核实；本批仅改取证
文档与登记表）。
