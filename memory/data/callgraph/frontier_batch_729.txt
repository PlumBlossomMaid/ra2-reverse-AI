=== 语义 ===

**信标删除器（__declspec::DeleteBeacon，ranking 带名）**——
thiscall 2 栈参 ret 8（this=信标管理器 0x89C3B0 推断）：信标存
储布局 this+0x00..0x5C = 8 组 × 3 槽（BeaconClass* 指针数组，
每组 0xC 步长）、this+0x60 = 信标计数。
① 指定模式（参1=a/参2=b 非 -1）：槽 idx = 3a+b，取槽指针；
② 扫描模式（参1=参2=-1）：外层 8 组 × 内层 3 槽遍历，找第一个
   槽+0xC bit1 置位的信标。
③ 公共判定：信标+0x110（house 索引）与当前玩家 [0xA83D4C]+0x30
   （house 索引）比较——不同且指定模式 → 继续；不同且扫描模式 →
   只清槽+0xC bit0/bit1（and 0xFC）返回不删除。
④ bit0 判定 + IsAlliedWith 双调（0x4F9A10 索引版 + 0x4F9A50 对
   象版）+ house+0x1F5 标志 == 0 → **完整删除路径**：[0x880A04]
   虚表槽 0x78 取 16B 结构 → 0x430650 BeaconClass::DrawRadar 从
   雷达移除 → delete 0x7C8B3D 删对象 → 组内找槽清空 → 计数--。
   任一条件不满足 → **简化删除路径**：直接 delete（不画雷达）。
⑤ 广播段（完整路径 + GameMode∈{0,5} + 组==当前 house + 扫描模
   式）：对其他玩家 esi=1..count-1 逐个：DebugLog(0x818AF0 格式
   串 + 玩家名) + Send_Global_Message（0x5410F0，this=0xA8E9C0，
   6 参：缓冲/0x3D=61/1/玩家名+0x28/0/0）——信标删除全网通知。
★语义统一：信标生命周期删除端——batch 241 SetPlaceBeaconMode
的放置端（0x430F30 CanPlaceBeacon 校验）与删除端（本函数）读写

=== 原版怪癖（照抄） ===

① 槽索引 idx = 3*a + b（参1 乘 2 再加参2 再叠加——lea 两连手写
   乘法 3x+y，非 imul）；
② 扫描模式标志 [esp+0x13]：两参 -1 才置 1，缺一个就是指定模式
   （-1 与其他值混用会算出负索引→[ebp+负*4] 越界读——原版不防）；
③ 扫描模式找的是槽+0xC **bit1**，完整删除判定却是 **bit0**（位
   语义分裂：bit1=扫描候选，bit0=删除资格）；
④ 判定失败（非盟友等）→ 简化路径**直接 delete 不画雷达**——
   但依然清槽+计数--（删除本身无差别，差别只在是否 DrawRadar/
   是否广播）；
⑤ 扫描模式且 house 不同 → **只清 bit 不删除**（游标式的"路过
   标记清除"——信标禁用但对象保留）；
⑥ 广播门控三重 AND：GameMode∈{0,5} 排除 + 组==当前 house +
   扫描模式（指定模式删除不广播——指定删只处理己方信标推断）；
⑦ 广播循环用 [0xA8DA84]-1 次（esi 从 1 起不含自己）+ 0x818AF0
   格式串过 DebugLog——信标删除的通知文本也走调试日志；
⑧ 完整路径先 DrawRadar 再 delete（先摘雷达显示再删本体——顺序
   敏感，反了会画已删对象）；DrawRadar 前虚表槽 0x78 取 16B 压
   栈再入参（8 参调用形态，虚表返回结构作第二参数）；
⑨ bit0 未置/非盟友/家标志非 0 → 全走简化路径**共用删除出口**
   （je/jne 全部落到 0x4312EB 同一个 delete）；
⑩ 计数==0 / 空槽 / 组内找不到 → 静默 ret 8（无报错）。
