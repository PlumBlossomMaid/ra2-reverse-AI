二、内核 0x7CB1CB 核验（disasm 0x7CB1CB 0x40）
------------------------------------------------
0x7CB1CB（0x7CB1CB-0x7CB1F8，cdecl 1 栈参 ret）：
  007cb1cb  push esi / mov esi,[esp+8]（★流槽）
  007cb1d0  push esi → call 0x7CB1F9（★★flushbuf 底层——batch 049 已登记
    「_flushbuf 底层」；0x7CA78C FILE 关闭内核同款被调！）
  007cb1d6  test eax,eax / pop ecx / je 0x7CB1E0（★flush 结果==0 继续）
    / or eax,0xFFFFFFFF（★flush 失败 → -1）/ pop esi / ret
  007cb1e0  test byte[esi+0xD],0x40（★流槽+0xD 标志 0x40 检查）
    / je 0x7CB1F5（★无 0x40 → 返 0）
  007cb1e6  push [esi+0x10]（★流槽+0x10 = OS 句柄 fd——batch 226 流槽布局）
    → call 0x7D30D1（★句柄操作——未登记）→ neg eax / pop ecx / pop esi
    / sbb eax,eax / ret（★★neg/sbb 惯用——fd 操作结果 0/-1）
  007cb1f5  xor eax,eax / pop esi / ret（★返 0）
★内核语义：flushbuf（0x7CB1F9）失败返 -1；成功继续 → 流槽+0xD 带 0x40 时对
+0x10（fd）调 0x7D30D1 并 neg/sbb 得 0/-1——「flush + fd 操作」两段式内核。

七、原版怪癖（照抄）
-------------------
① 空流槽走 0x7CB25E 独立路径（非直接返 0/非锁包裹——空指针有专门处理）；
② 「流锁 Enter → 内核 → 流锁 Leave」三步无返回值合并（内核结果 edi 透传
   ——Leave 返回值丢弃）；
③ 内核 0x7CB1CB：flushbuf（0x7CB1F9）失败返 -1（or eax,0xFFFFFFFF）——
   flush 失败直接短路；成功才检查 +0xD 0x40 并操作 fd（+0x10）；
④ fd 操作用 neg/sbb 惯用（call 0x7D30D1 → neg eax → sbb eax,eax——结果
   0/-1，非直接比较）；
⑤ 流槽 +0xD 带 0x40 位才操作 fd（无 0x40 返 0——字符串流/无句柄跳过）；
⑥ 调用点全以 [0xAA0468]（会话区流槽全局）为参 + [0x7E11EC] 队列推进成对
   （释放+队列推进惯用——batch 260 的 0x53E770 Esc 分支同款）。
