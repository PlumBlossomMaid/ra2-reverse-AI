0x006C8C40 / 0x006C8C50 —— timeGetTime() >> 4（逐字节全同的孪生）
================================================================================
129 callers（0x6C8C40）。两函数反汇编逐字节完全相同，各自后跟 6 个 nop：

    006c8c40  call dword ptr [0x7e1530]    ; ★ IAT 槽 0x7E1530
    006c8c46  shr eax, 4                   ; 结果 >> 4
    006c8c49  ret
    ...6 nop...（对齐填充）
    006c8c50  call dword ptr [0x7e1530]    ; 完全相同的第二份
    006c8c56  shr eax, 4
    006c8c59  ret

**导入表解析实锤**：IAT 槽 `0x7E1530` = `WINMM.dll!timeGetTime`。
所以这是 `timeGetTime() >> 4` 的封装。

语义注：timeGetTime 返回毫秒；`>>4` 即除 16，得 ~62.5 Hz 的粗粒度时标。
⚠️ 「这就是 RA2 的游戏帧 tick」是**推断**——值域吻合但没有反汇编证据
把这个返回值连到帧循环，故不写成断言。已实锤的只是「毫秒时标右移 4 位」。

同字节孪生的存在说明它是编译器按 TU 展开的副本（与 batch 059 的
0x43AE50/0x43AE80 同理），**但本批未做归一化逐字节比对**（肉眼比对 3 条
指令 + 6 nop 填充全同），故标 verified 而非「已证副本」的更强措辞。

0x00431B80 —— BufferIOFileClass::~BufferIOFileClass（虚表回填 + 条件删缓冲）
================================================================================
109 callers（符号名来自 functions.tsv 的 USER_DEFINED，即 YRpp 覆盖，非本
exe 实锤）。反汇编 0x40 字节：

    00431b80  push ebx / push esi
    00431b84  mov esi, ecx                  ; this
    00431b86  mov eax, [esi+0x30]           ; 缓冲指针字段
    00431b89  mov dword ptr [esi], 0x7e3a2c ; ★ 回填虚表 0x7E3A2C
    00431b8f  cmp eax, ebx                  ; ebx=0
    00431b91  je 0x431ba7                   ; 无缓冲 → 跳过 delete
    00431b93  cmp byte [esi+0x24], bl       ; 持有标志
    00431b96  je 0x431ba4                   ; 为 0 则不删
    00431b98  push eax
    00431b99  call 0x7c8b3d                 ; operator delete
    00431b9e  add esp, 4
    00431ba1  mov byte [esi+0x24], bl       ; 清标志
    00431ba4  mov dword [esi+0x30], ebx     ; 清缓冲指针
    00431ba7  mov ecx, esi
    00431ba9  mov dword [esi+0x34], ebx     ; 清 +0x34
    00431bac  mov byte [esi+0x25], bl       ; 清 +0x25
    00431baf  mov byte [esi+0x27], bl       ; 清 +0x27
    00431bb2  mov byte [esi+0x28], bl       ; 清 +0x28
    00431bb5  mov byte [esi+0x29], bl       ; 清 +0x29
    00431bb8  call 0x65ca00                 ; ★ 基类析构
    00431bbd  pop esi / pop ebx / ret

判据（为什么这是析构而非普通方法）：
① 首条副作用是 `mov [esi], 0x7E3A2C` 把虚表回填为基类虚表——C++ 析构的
   标志性动作（构造正序建虚表、析构逆序拆虚表）。
② 条件 delete 受 `+0x24` 标志门控（owns-buffer 语义），与 batch 059 的
   0x43AE50 同一模式但字段布局不同（BufferIOFile 的持有标志在 +0x24，
   0x43AE50 的在 +0x08）。
③ 末尾 `call 0x65CA00` 是基类析构链。

结构布局（partial，未逐一实锤字段语义）：
  +0x00 vtable(=0x7E3A2C)   +0x24 owns-buffer 标志   +0x25/+0x27/+0x28/+0x29 标志
  +0x30 缓冲指针            +0x34 第二指针/长度
⚠️ 未实锤：基类 0x65CA00 是谁；+0x25/+0x27..29 各标志含义。

0x006C8C80 / 0x006C8CB0 —— 常量计算与取用（partial，pow 身份存疑）
================================================================================
0x6C8C80：
    fld qword [0x7E1710]        ; = 256.0（读字节实锤）
    fld qword [0x7E1708]        ; = 2.0  （读字节实锤）
    call 0x7C8FB0               ; 双入参数学函数
    fadd st(0), st(0)           ; 结果 ×2
    sub esp,8 / fstp [esp]
    call 0x4CAC40               ; sqrt（batch 058 已证）
    fstp qword [0xB0BEF0]       ; 存结果

若 0x7C8FB0 是 pow(base,exp)：pow(256,2)=65536，×2=131072，sqrt=362.0386…
0x6C8CB0：`fld [0xB0BEF0]; fdiv [0x7F3F48]`（0x7F3F48=60.0，读字节实锤）。

⚠️ **存疑**：0x7C8FB0 的内部带 fnstcw + 指数掩码检查（and/cmp 0x7ff00000），
这是「双入参且需处理无穷/特殊值」的数学函数形态——pow、fmod、atan2 都符合，
但本轮**未逐条确认 0x7C8FB0 的主干算法**，故「pow」只是推断。
若它是 pow，则 [0xB0BEF0]=362.038…、0x6C8CB0 得 362.038/60≈6.034；
若它是 fmod/atan2 则结果完全不同。**不写成断言，留待下批反汇编 0x7C8FB0 主干。**
