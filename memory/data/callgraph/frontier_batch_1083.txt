一、链语义（disasm 头/中/尾复核，0x7C7371-0x7C7DF5）
------------------------------------------------
头部（0x7C7371-0x7C73E0）：
007c7371  55                     push ebp
007c7372  8bec                   mov ebp, esp
                                          ; 6 寄存器保存（esi/edi/ebx/ecx/edx…）
007c73d6  …                      mov ebx,[ebp+0x1c]    ; ★param4（ndigits?）
                                          ; mov cx,[ebp+0x10]  ← 16 位 param2
                                          ; mov dx,[ebp+0x14]  ← 16 位 param3
007c73e8  …                      cmp cx,8              ; ★cx=8：十进制 double
                                          ; cmp cx,0x10         ; ★cx=0x10：十进制
                                          ;   long double —— 主路径
                                          ; cmp dx,2 / cmp dx,1  ; ★dx=2 BINARY /
                                          ;   dx=1 HEX 次进制
007c73f8  …                      jmp dword[ebx*4+0x7c7778]  ; ★★跳转表 1
                                          ;   （8 入口 0x7C73E2/0x7C73F8/0x7C7408/
                                          ;     0x7C7418 + 4 个伪目标——表尾越界，
                                          ;     对应 digit 分组 0/1/2/3 移位路径）
中段：三个 `sub ebp,x; push ebp; shr ebp,4; inc ebp` 分支
      ——digit 按 4 位分组（每轮 4 bit 查表）
      `add eax,[edx*2+0x879b30]`（★表 3：word 元素
      0,1,3,4,7,8,10,11…——平方 digit 偏移）
      `mov [edi],ax` / `add edi,2`（写 word 输出）
      `mov dx,[edx+0x87b170]`（★表 1：word 元素
      0,64,128,192,256 重复——digit 周期）
      `or dl,[ebx+0x87bc90]`（★表 2：byte 元素
      0,2,4,…,30——digit×2 半字节位）
      `cmp eax,0x7fff; jg` / `cmp eax,0xffff8000; jl`
      （★16 位饱和钳制 -32768..32767）
尾部（0x7C7DC0-0x7C7DF5）：一排 `mov eax,0x7fff / jmp`
      / `mov eax,0xffff8000 / jmp` 展开块（钳制出口），
      后接 `add edx,[eax*2+0x87b170]`（表 2 二段）

★语义：**CRT `_CVTBUF`（浮点→digit 串转换核心——推断
名）**——cdecl 变参（param1=输出缓冲、param2/param3=16
位进制参数、param4=ndigits）：MSVC6 CRT _cvt 家族
（_ecvt/_fcvt/_gcvt/sprintf %e%f%g 共用）的进制转换引
擎——cx=8（__CVTFIRST_DECIMAL double）/cx=0x10（十进制
long double）主路径，dx=1（HEX）/dx=2（BINARY）次进制
分派；三张全局查表（0x879B30/0x87B170/0x87BC90）驱动
digit 生成；16 位饱和钳制（0x7fff/0xffff8000）防溢出。

★E8 被调者全扫（0x7C7371-0x7C7DF5 区间）：**零真实子调
用**（唯一命中 0x8C7C7A19 = E8 字节在指令中间的数据误
读伪目标）——纯跳转表/查表计算引擎，无 call 依赖。

★原版怪癖（照抄）：
  ① 16 位参数分派（cx/dx 各自 cmp 链——cvtype 打包在 16
     位槽，编译器拆半字读取）；
  ② 双跳转表（0x7C7758 首 4 入口有效 + 0x7C7778 首 4 入
     口有效，后 4 个是越界伪目标——digit 分组 0..3 只有
     4 路但表留 8 槽）；
  ③ 三查表分工（0x879B30 digit 偏移 / 0x87B170 周期 /
     0x87BC90 半字节位）；
  ④ 16 位饱和钳制展开块（0x7C7DC0 起一排 mov eax,±0x7fff/
     0xffff8000 + jmp 回钳制出口——编译器钳制展开）；
  ⑤ `sub ebp,x; shr ebp,4; inc ebp` 分组（每轮 4 bit 进
     位——digit 按 16 进制半字节推进）。

三、三态判定（为何 crt_runtime_verified 而非 cpp_reimplementation）
----------------------------------------------------------------
1. 归属：0x7C7371 = MSVC6 CRT `_CVTBUF`——0x7C-0x7D =
   MSVC6 静态 CRT（ra2_code_region_layout_crt_provenance）；
   16 位 cvtype 分派 + _cvt 家族查表为 MSVC6 标准形态。
2. 依赖：三全局查表（0x879B30/0x87B170/0x87BC90）+ 双跳
   转表——重写 gamemd 时用等价运行时（_ecvt_s/自写进制
   转换）代替。
3. 零子调用纯计算 → 本可 REIMPL，但 `_CVTBUF` 的进制语
   义 + 查表值域属商业库内部（非字节级可验证独立算法），
   按商业库纪律归档，不写 C++ 模型不做 golden——与 batch
   1043 _itoa 家族（REIMPL）的界线：_itoa 的 digit 算法
   全在代码内零表依赖，_CVTBUF 依赖三张未语义化全局表。
→ 状态：crt_runtime_verified（头/中/尾 + 零子调用全扫
交叉；函数名「_CVTBUF 浮点转 digit 核心」为推断交叉标
注）。
