★语义：**Westwood MMX 像素合成函数（四兄弟族第二件，推断
名）**——与 batch 1119 0x7DF280 逐语义同构：
  ① 双指针双循环（内层逐列字节源 +1/字目标 +2，外层行步
     进 +[ebp+0x10]/+[ebp+0x14]）；
  ② 每像素：源字节（0 → 跳过）作 α → 目标 word 作表索引
     → [edx+ebx*4] 32 位调色板查表 → MMX punpcklbw/psrlw 8/
     pmullw ×α/psrlw 8/paddusb 饱和/psrlw 2；
  ③ RGB565 打包写回目标 word（本件移位/掩码变体）；
  ④ ★本件有 emms 收尾（0x7DF778）。

★调用点（探针 E8 实测 1 处 0x5FFAF0）：宿主 0x5FFA 区调度
  （batch 1119 已证）：cmp [0xAC1838],edx → je 选 6 参变体
  （0x7DEEFA）/jne 选 7 参变体（本件）；7 参 push 顺序
  eax/edi/0x100/esi/edx/ecx/ecx，add esp,0x1C 清理。

★E8 被调者：零（纯 MMX + 查表内联）。

★逐字节 diff（_probe_7df640_diff.py）结果：头对齐 1 处
  （0x7DF321 vs 0x7DF6E1 len=1）；尾对齐 17 处全部落在布局
  /NOP 填充区（0x7DF2xx vs 0x7DF6xx，len 3-37）——即同模板
  仅对齐填充分布 + 打包尾段 + 布局位置不同，**核心 MMX 链
  逐字节一致**。

★原版怪癖（照抄，含族间差异）：
  ① 本件有 emms（0x7DF778）——batch 1119 的 0x7DF280 无
     emms：★族件间 MMX 收尾不一致（编译器实例差异），重写

三、三态判定（为何 semantics_verified 而非 crt_runtime_verified）
---------------------------------------------------------------
1. 归属：0x7DF640 = **Westwood 自有代码**——①MMX 像素合成
   （punpcklbw/pmullw/paddusb）非 MSVC6 CRT 形态；②32 位调
   色板查表 + RGB565 位拼为渲染管线特征；③宿主 0x5FFA 区渲
   染调度（cmp [0xAC1838] 分派 7/6 参形态）；④与 batch 1119
   0x7DF280 四兄弟族同模板（核心 MMX 链逐字节一致，布局/
   打包/emms 差异由 diff 实锤）。
2. 依赖：无子调用，纯 MMX + 表——重写时按像素合成语义等
   价实现。
3. 复刻纪律：Westwood 自有代码——不按商业库归档；像素合
   成非 RMG 管线依赖，保留 semantics_verified。
→ 状态：semantics_verified（MMX 链逐字节 diff + 宿主调度 +
