一、链语义（disasm 全 29B + 调用宿主交叉，0x7C1130-0x7C114C）
--------------------------------------------------------------
签名（确认）：thiscall + 1 栈参（ecx=this 对象、[esp+4]=
edx 入参），返回 eax：成功 0 / 失败 -1。

主体（0x7C1130-0x7C114C）：
007c1130  inc edx                          ; ★入参 +1
007c1131  lea eax, [ecx+0x112]             ; ★eax = this+0x112
                                           ;   （缓冲/结构地址）
007c1137  and edx, 0xfffffffe              ; ★(edx+1) & ~1
                                           ;   （偶数化/对齐）
007c113a  push edx                         ; 参4 = 对齐值
007c113b  push eax                         ; 参3 = this+0x112
007c113c  push 5                           ; ★参2 = 5
007c113e  push ecx                         ; 参1 = this
007c113f  call dword[ecx+0x40]             ; ★★虚表槽 0x40 派发
                                           ;   （4 参）
007c1142  add esp, 0x10                    ; 清 4 栈参
007c1145  neg eax                          ; eax = -ret
007c1147  sbb eax, eax                     ; eax = (ret!=0) ?
                                           ;   -1 : 0
007c1149  and al, 0xfd                     ; ★al &= 0xFD →
                                           ;   0xFF & 0xFD = 0xFD
                                           ;   ……失败值保留
                                           ;   0xFD? 见怪癖②
007c114b  dec eax                          ; eax -= 1
007c114c  ret

★语义：**MSVC6 CRT Winsock 协议枚举包装器（推断名——
EnumProtocols 类包装：固定参 5 + this 缓冲 + 对齐尺寸，
返回值归一化为 0/-1）**——thiscall 1 栈参：
  ① 尺寸入参 edx+1 再 `& ~1` 偶数化（对齐）；
  ② 4 参派发虚表槽 0x40（this、5、this+0x112、尺寸）；
  ③ 返回值经 `neg/sbb/and/dec` 四步归一化。
  = CRT Winsock 库把可变参 API 包成虚表派发（槽 0x40 由派
  生类实现——具体 API 由对象类型决定），失败统一 -1。

★返回值归一化推演（实锤序列 neg/sbb/and al,0xFD/dec）：
  ret≠0 → neg 得非零 → sbb 得 0xFFFFFFFF → &0xFD 不变
  → dec → 0xFFFFFFFE？→ 与 cmp eax,-1 比较（宿主 0x7C290C）
  不符……
  按 sbb 语义重推：neg eax 置 CF=(eax!=0)；sbb eax,eax →
  eax = -(CF) = 0 或 -1。ret==0 → CF=0 → eax=0 → and
  al,0xFD → 0 → dec → **0xFFFFFFFF（-1，失败）**；ret≠0 →
  eax=-1=0xFFFFFFFF → &0xFD → 0xFFFFFFFD → dec →
  **0xFFFFFFFC**？仍不符——
  → 如实登记：**归一化中间值语义未完全闭合**（dec 后的具
  体数值需动态验证；宿主 0x7C290C 以 cmp eax,-1 判成功，
  结合 0x7C290F jne 分支推断「成功值 == -1」或「失败值
  == -1」二者之一，本批不臆断，标「未确认」）。

★调用点（探针 E8 实测 1 处 0x7C2907）：宿主 0x7C28xx 区
  （CRT 字体/协议域）：cmp dword[0x50494C43],edi（★★
  'CLIC' ASCII 常量比较——'CLIC' = 0x50494C43 字节反序即
  "CLIC"，推断为字体/编码标识魔数）/je 0x7C2905 → mov
  ecx,ebx / call 0x7C1130（★本批）→ cmp eax,-1 / jne
  0x7C2C2F（成功分支）/jmp 0x7C2772（失败重试循环）；另
  分支 cmp eax,0x464E494C（★'LINF' 魔数）/jne → call
  0x7C1150（★同族下一包装器，scan 池候选）——宿主按魔数
  分派到不同包装器（本批处理 "CLIC" 分支）。

★E8 被调者：零 E8（唯一调用经虚表槽 0x40 间接）。

★全局：读 [0x50494C43]（★'CLIC' 魔数常量，实为 .text 内
  立即数双字——非真实全局，编译器把 4 字节立即数直接编
  码成 [abs] 形式，见怪癖③）；零写。

★原版怪癖（照抄）：
  ① `push 5` 硬编码参数 2（固定 API 子号/族）——包装器把
     可变参固定为 5；
  ② **立即数被编码成 [abs] 内存读**（cmp dword ptr
     [0x50494C43],edi）——0x50494C43 不是变量，是 ASCII
     "CLIC" 的字节反序立即数被 MSVC6 错误/特殊编码成绝对
     内存操作数（MSVC6 对 32 位常量的编码陷阱，执行时读
     该地址内存——实为代码区字节；此形态照抄）；
  ③ 尺寸参数 `inc edx / and edx,0xFFFFFFFE` 偶数化（对齐
     到 2）——而非 `(n+1)&~1` 的明显写法（等价但分开）；
  ④ 返回值四步归一化（neg/sbb/and al,0xFD/dec）——省分支
     的算术技巧，语义未完全闭合（见上「未确认」）；
  ⑤ 4 参派发后 add esp,0x10 一次清（含 this 也 push）——
     thiscall 却按 cdecl 传 this（虚表槽按对象约定）；
  ⑥ 缓冲地址 this+0x112 硬编码（对象内嵌 0x112 偏移缓冲）
     ——与宿主 +0x7D0 记录（batch 1219）不同偏移，同对象
     不同域。
