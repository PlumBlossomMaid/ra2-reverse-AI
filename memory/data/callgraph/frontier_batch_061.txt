与 batch 059 的 `0x7B46F0`（163 callers）逐指令完全相同——同一个

**与 0x5657A0 / 0x565730 的家族关系（三兄弟对比）**：

| 维度 | `0x5657A0` | `0x565730` | `0x578080` |
|---|---|---|---|
| 坐标表 | this->[0x13C] | this->[0x13C] | **全局 [0x87F924]** |
| 边界 | 硬编码 0x40000 | this->[0x140] | **全局 [0x87F928]** |
| 入参 | 格坐标(int16) | 8.8 定点 | 8.8 定点 |
| 哨兵 | 0xABDC50 | 0xABDC50 | 0xABDC50 |
| 越界记录 | [0xABDC74] | [0xABDC74] | [0xABDC74] |
| 命中后 | 返回格指针 | 返回格指针 | **再调 0x47B3A0 取层高** |

即三者共用同一套 idx 布局、哨兵、诊断全局，但「表来源」分两类：
0x5657A0/0x565730 用实例字段（MapClass 成员），0x578080 用全局
（等价于直接用 MapClass::Instance）。0x578080 多一步：命中格后调
`0x47B3A0`（据名字应为 GetCellFloorHeight 的主体）返回层高。

⚠️ 保留边界：① 0x47B3A0 内部未取证；② 全局 [0x87F924]/[0x87F928] 与
实例字段 [0x13C]/[0x140] 是否恒等值未实锤（前者应是后者的镜像，
但未找到写入点的对照证据）。

================================================================================
0x007B6780 / 0x007B67C0 —— NULL 安全的字符串相等判定（邻域观察）
================================================================================
紧邻 0x7B6760 之后。0x7B6780：

    007b6780  mov eax, [ecx]               ; this->str
    007b6782  mov ecx, [esp+4]             ; arg
    007b6786  test eax, eax / jne 0x7b6793 ; this->str 非 NULL → 比较
    007b678a  test ecx, ecx / jne 0x7b6793 ; 或 arg 非 NULL → 比较
    007b678e  mov al, 1 / ret 4            ; 双 NULL → 相等返 1
    007b6793  test eax, eax / je 0x7b67ad  ; 单 NULL → 不等
    007b6797  test ecx, ecx / je 0x7b67ad
    007b679b  push ecx / push eax
    007b679d  call 0x7ca5d3                ; strcmp
    007b67a5  test eax, eax / sete al      ; strcmp==0 → 相等
    007b67aa  ret 4
    007b67ad  xor al, al / ret 4           ; 不等返 0

即「双 NULL 视为相等、单 NULL 视为不等、都非 NULL 则 strcmp」的
NULL 安全 `operator==`。**返回值是布尔**（sete/sbb），与 batch 059 的
0x7B4710 一致——这个模块的字符串比较一律返回 bool 而非 C 的三态。

0x7B67C0 是变体（先 `mov ecx,[ecx]` 解引用再比）。
⚠️ 本条为邻域观察，未单独核对调用者，不登记为独立结论。
