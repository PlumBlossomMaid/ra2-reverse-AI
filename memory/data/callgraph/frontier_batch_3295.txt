## 取证要点（本批实锤）

### 布局
4×3 行主序 12 floats（与 YRpp Matrix3DStruct::Data[12] 一致）：
行 0 = m[0..3]（X,Y,Z,平移），行 1 = m[4..7]，行 2 = m[8..11]。

### 精度怪癖（照抄清单）
1. **FPCW=0x0E7F = PC=53 位 + RC=chop**：x87 栈上中间运算按 53 位双精度向零
   截断，等于 C++ double 在 FpuChopScope（FE_TOWARDZERO）下的逐位行为。
2. **sin/cos 窄化不对称**：
   - RotateX/RotateY：先调 Sin（`fstp dword` 窄化成 float32 存栈）后调 Cos
     （留在 x87 栈，53 位不窄化）——`fmul dword [esp+0x28]` 读的就是窄化后的 sin。
   - RotateZ：**恰好相反**——先调 Cos（窄化存栈）后调 Sin（留栈）。
   - 查表 sin/cos 的返回值本身就是 float 位形（无损扩展成 double），窄化对
     数值无影响——但函数入口的调用顺序就是语义，照抄（golden 实证）。
3. **RotateVector 三行点积累加顺序不对称**（行 1：m[1]*v1 + m[2]*v2 先、m[0]*v0
   后；行 2/3：m[5]*v1 + m[4]*v0 先、m[6]*v2 后）——RC=chop 下顺序即末位，必须
   照抄。反汇编逐条核对（0x5AF4D7-0x5AF538）。
4. **Construct 的 fchs**：0x5AE735 `fld [esp+8]; fchs; fstp [esp]` 对参数 1 取负
   后做第三次 RotateZ——旋转顺序是 Rz(a1)→Rx(a2)→Rz(−a1)，不是一次性欧拉角
   展开，照抄序列（golden 证）。
5. RotateX/Y/Z 都**跳过平移列**（只转 3×3 子块），Translate 只动平移列——分工
   明确，无重叠写。

## 验证方法论

golden 生成：`code/randmap/dump_matrix_golden.py`（新增，正式产物）
- Oracle 把 gamemd.exe 按 ImageBase 0x400000 映射后，`emu_start` 直接调用
  原版矩阵函数（含内部 call 0x4CACB0/0x4CAD00 都跑真身），FPCW=0x0E7F。

  各 48 / RotateVector 20），输入 = 确定性伪随机矩阵 + 特殊角度（π/4、π/2、
  π、±π/6、±100、1e-6…），输出 12 或 3 个 float 位形。
