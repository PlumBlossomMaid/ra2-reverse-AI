0x6406F0  PreviewClass::~PreviewClass（23 callers，0x16B）
================================================================================
ranking.tsv 符号名 PreviewClass::~PreviewClass（confirmed_identity 列非空，
YRpp 无 JMP 宏覆盖 → 按推断名登记）。调用方含 0x5958E0/0x595BC0/0x596300/
0x596C70（0x595xxx-0x596xxx 区 = RMG 主流程区，QWEN.md 已确认 MapGen.cpp
TU 在 0x5956E7-0x59A63A）——预览窗口随 RMG 阶段释放。

机器码（全 0x16B）：
    mov esi, ecx
    mov ecx, [esi]               ; ★ this->[0]（子对象/资源指针）
    test ecx, ecx / je done
    mov eax, [ecx]               ; 子对象虚表
    push 1
    call [eax]                   ; ★ 子对象虚表槽 0（析构，arg=1）
    mov [esi], 0                 ; ★ 指针置 NULL
  done:
    ret

语义：**单指针成员的释放析构**——this->[0] 指向的对象若非空则调其虚表槽 0
（带参 1）销毁并置 NULL。是「PreviewClass 持有一个动态子对象」的标准析构形态。
⚠️ partial：子对象类型与虚表槽 0 的精确语义（arg=1 的意义）未实锤。

0x4E37D0 / 0x4E5940  索引↔值查表孪生对（各 23 callers，各 0x60B）
================================================================================
两个函数形态完全同构（一个在 0x4E37xx 区、一个在 0x4E59xx 区），都是
「索引 → 值」的正向查表，且各自紧邻一个「值 → 索引」的反向查表（0x4E3830 /
0x4E59A0）——四者构成两对完整的双向映射。

0x4E37D0（正向，0x60B 全读完）：
    mov eax, ecx
    test eax, eax / jne next0
    mov eax, 0x6a1 / ret          ; ★ 0 → 0x6A1
  next0: cmp eax, 1 / jne next1
    mov eax, 0x510 / ret          ; ★ 1 → 0x510
  next1: cmp eax, 2 / jne next2
    mov eax, 0x513 / ret          ; ★ 2 → 0x513
  next2: cmp eax, 3 / jne next3
    mov eax, 0x51e / ret          ; ★ 3 → 0x51E
  next3: cmp eax, 4 / jne next4
    mov eax, 0x514 / ret          ; ★ 4 → 0x514
  next4: cmp eax, 5 / jne next5
    mov eax, 0x51f / ret          ; ★ 5 → 0x51F
  next5: cmp eax, 6 / jne next6
    mov eax, 0x520 / ret          ; ★ 6 → 0x520
  next6: sub eax, 7 / neg / sbb / and eax, 0xfffffade / add eax, 0x521
    ret                            ; ★ ≥7 → 0x521 + (0x... 溢出钳位)

0x4E5940（正向，0x60B 全读完）：同构——0→0x76D、1→0x76E、2→0x76F、3→0x770、
4→0x771、5→0x772、6→0x773、≥7→0x774（末段 and 0xfffff88b + add 0x774）。

紧邻反向函数（各 0x40B 起）：
    0x4E3830：cmp 0x6A1→0 / cmp 0x510→1 / cmp 0x513→2 / ...（与正向严格互逆）
    0x4E59A0：cmp 0x76D→0 / cmp 0x76E→1 / ...（与正向严格互逆）

语义：**枚举索引 ↔ 内部 ID 的双向查表**——正向把紧凑索引（0..N）映射到稀疏
内部 ID（0x510-0x521、0x76D-0x774），反向把内部 ID 映回索引；索引 ≥7 走
「+1 固定」的尾段（0x521 起连续值）。两套表数值区间不同但结构同源——是
「对象类型索引 ↔ 资源/类型 ID」的标准双向映射实现。⚠️ 具体映射对象（哪两类
枚举 ↔ 哪些 ID）未对齐 YRpp（0x4E3xxx/0x4E5xxx 区无符号覆盖）。

★跨批次连接：尾段 `sub/neg/sbb/and/add` 的「溢出钳位到固定值」惯用法与
batch 083 的 x87 向零截断族同思路（都是「越界归一」）；正向/反向紧邻成对
与 batch 089 孪生副本、batch 103 尺寸孪生对不同——成对映射是引擎「索引
体系」的常见布局。
