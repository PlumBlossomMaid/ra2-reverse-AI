**与 0x005657A0 的关系（两者是孪生，本轮交叉确认）**：

| 维度 | `0x5657A0` | `0x565730` |
|---|---|---|
| 坐标表 | `this->[0x13C]` | `this->[0x13C]`（同一张） |
| 索引 | `x + (y<<9)` | 同（两轴各自 >>8 后同布局） |
| 边界 | 硬编码 `cmp eax, 0x40000` | **实例字段 `this->[0x140]`** |
| 入参 | 已是格坐标（`movsx word`） | **8.8 定点数**，需先右移 8 |
| 越界哨兵 | `0xABDC50` | `0xABDC50`（同一） |
| 越界记录 | `mov [0xabdc74], edx` | 同 |

两函数共用 `[0x13C]` 格子表、`[0xABDC50]` 哨兵、`[0xABDC74]` 诊断全局，
说明 `0x565730` 是「实数坐标 → 格」的入口，`0x5657A0` 是「格坐标 → 格」的
直接入口。

★ **`cdq / and edx,0xff / add eax,edx / sar eax,8` 是 8.8 定点转整数的经典序列**
（MSVC 的 `_ftol` 之外的整数定点路径）：先按低字节符号扩展，再算术右移 8。
符号位由 `cdq` 产生、由 `and 0xff` 取出并加回，故负坐标能正确向下取整。

⚠️ 未实锤：`this->[0x140]` 的语义（很可能是格子表容量或行列跨度），
未找到写入点，故不写成「= side²」之类断言。

即「安全 delete 单一指针成员并自清空」。`0x7C8B3D` 是 operator delete

紧邻的 `0x007B4710`（40B 起）是**两字节一组的 strcmp**（手写展开）：

    007b4710  mov eax, [ecx] / push esi
    007b4713  mov esi, [esp+8]
    007b4717  test eax, eax / jne ...      ; 任一为 NULL → 跳出
    007b471b  test esi, esi / jne ...
    007b471f  mov al, 1                    ; 双 NULL → 相等，返回 1
    ...
    007b472e  mov dl, [eax] / mov bl, [esi] / mov cl, dl
    007b4734  cmp dl, bl / jne 0x7b475e
    007b4738  test cl, cl / je 0x7b4752    ; 命中 NUL → 视为相等
    007b473c  mov dl, [eax+1] / mov bl, [esi+1] / ...   ; ★ 一次比 2 字节
    007b4752  xor eax, eax

**注意返回值是布尔（相等返 1）而非 C 的 0/负数** —— 是 `stricmp`-family
的 `bool operator==` 形态，不是标准 `strcmp`。⚠️ 该函数未单独登记（不在
本批扇入 top 内），仅作为邻域观察记录。
