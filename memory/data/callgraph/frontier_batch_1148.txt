★语义：**MSVC6 CRT _filelength 文件长度获取器（推断名——
标准 C 库 `_filelength`）**——cdecl 1 参：
  ① fd 边界检查（[0xB78B80] _nhandle）+ 槽位位检（
     [0xB78A80] 组表 & osfile 位 1=FOPEN）——无效 fd → 
     errno=9(EBADF) + 返回 -1；
  ② 有效 → 临界区（0x7D96A8/0x7D9707）内三连 _lseek：
     SEEK_CUR 存当前位置 → SEEK_END 取长度 → 若位置/长度
     不同则 SEEK_SET 恢复原位；
  ③ 返回长度（ebx），-1 哨兵全路径。
  = MSVC6 `_filelength` 标准实现（存位→取尾长→复位），与
  VC6 CRT 源码行为逐行吻合。

★调用点（探针 E8 实测 1 处 0x7BF351）：宿主 0x7BF350 起
  短函数（文件 API thunk 链：前段 0x7BF330-0x7BF34F 调
  0x7D7638 检查、本段 0x7BF350-0x7BF363 调 0x7DDF78 后
  `mov [edx],eax` 写长度到输出参 + `xor eax,eax` 返 0 成功、
  后段 0x7BF364 起调 0x7D2A74）——0x7BF3xx CRT 文件 API
  封装域。

★E8 被调者：0x7D96A8（★★batch 034 临界区槽获取）+ 
  0x7D769D（★★batch 049/019 _lseek 族句柄校验+SetFilePointer
  包装——调用 3 次）+ 0x7D9707（★★batch 034 临界区槽释放）
  + 0x7D168E（★★batch 034 per-thread errno +8）+ 0x7D1697
  （★★batch 018 per-thread 状态 +0xC）——**五个依赖全部已
  登记**。

★原版怪癖（照抄）：
  ① 边界检查单独一路（[0xB78B80] jae）与槽位位检（组表位
     1）**分两处检查**——第一条是 _nhandle 上界、第二条是
     osfile FOPEN 位，任一不过都走同一错误路径；
  ② 槽步进 `lea eax,[eax+eax*8]`（×9）后 `[ecx+eax*4+4]`
     ——组表 36B/项、位字节在第 4 偏移（batch 034 同款布
     局）；
  ③ 三连 _lseek 顺序为先存位再取尾长再恢复——位置/长度
     相等时跳过恢复（edi==ebx je）——两分支独立处理；
  ④ 错误路径返回 -1 且 eax 直接 or eax,-1（非 xor+dec）
     ——同 batch 049 族风格；
  ⑤ errno=9（EBADF 无效句柄）硬编码 + 清 per-thread 状态
     位（and [eax],0）——错误报告+状态复位成对。
