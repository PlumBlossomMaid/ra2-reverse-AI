0x0052AEC0 —— 三字段构造器（19B，ret 4）（5 callers，全 0x13=19B 读完；deps=127）
================================================================================
机器码（全 19 字节，无分支）：
```
0052aec0  mov eax, ecx          ; ★this
0052aec2  mov ecx, [esp+4]      ; ★栈参1
0052aec6  mov [eax], ecx        ; this+0 ← 栈参1
0052aec8  xor ecx, ecx
0052aeca  mov [eax+4], ecx      ; this+4 ← 0
0052aecd  mov [eax+8], ecx      ; this+8 ← 0
0052aed0  ret 4
```
语义：**三字段构造器（推断名）**——`__thiscall` 单栈参：首字段取参数，后两字段
清零。三字段布局（4/4/4）是典型「句柄 + 两个状态」小对象。
★邻函数对照（同 call 内顺带读出）：`0x0052AEE0` = `push esi / mov esi,ecx /
call 0x631C80 / test byte [esp+8],1 / je … / push esi …`——**标量删除析构**
（典型的「先调真析构 0x631C80，再按标志位决定是否 operator delete」形态），
紧随其后且共用同一 this 布局，**两函数是一对**。
⚠️ partial：宿主类、三字段各自语义、0x631C80（析构体）身份。

0x00557AC0 —— 带边界钳制的数组 getter（30B，ret 4）（5 callers，全 0x1E=30B 读完；deps=77）
================================================================================
机器码（全 30 字节）：
```
00557ac0  mov eax, [ecx+0x44]   ; ★this+0x44 = 元素数 n
00557ac3  test eax, eax
00557ac5  jne 0x557aca
00557ac7  ret 4                 ; ★n == 0 → 直接返回（eax 保持 0）
00557aca  mov edx, [esp+4]      ; ★请求索引
00557ace  dec eax               ; n - 1
00557acf  cmp edx, eax
00557ad1  jl 0x557ad5
00557ad3  mov edx, eax          ; ★索引钳制到 n-1（越界不报错）
00557ad5  mov eax, [ecx+0x38]   ; ★this+0x38 = 数组基址
00557ad8  mov eax, [eax + edx*4]
00557adb  ret 4
```
语义：**带边界钳制的数组 getter（推断名）**——`this+0x44` 为元素数、`this+0x38`
为 dword 数组基址；请求索引 ≥ n 时**静默钳制到 n-1**，n==0 时返回 0。
★原版怪癖（照抄）：① **越界索引静默钳制**（不报错、不返哨兵，直接取最后一项
——调用方传越界值不会崩但会拿到错项）；② n==0 走早退（eax 未被赋值，返回
**未定义残留值**？——不进 dec/cmp 分支，eax 就是 `[ecx+0x44]` = 0，故返回 0）。
★邻函数对照（同 call 内顺带读出，**同族兄弟**）：
```
0x00557AE0  mov eax, [ecx+0x16C]   ; ★固定索引 this+0x16C
0x00557AE6  mov edx, [ecx+0x44]    ; 元素数
0x00557AE9  cmp edx, eax
0x00557AEB  jg 0x557af0            ; ★仅当 count > this+0x16C 才取值
0x00557AED  xor eax, eax / ret     ; 否则返回 0
0x00557AF0  mov ecx, [ecx+0x38] / mov eax, [ecx+eax*4] / ret
```
即**同一个 `this+0x38` 数组的第二个 getter**，索引固定为 `this+0x16C`，且
**反向门控**（count 不大于索引就返回 0）——与 0x557AC0 的「钳制」形成鲜明对比
（一个钳制取末尾、一个判空返回 0），**同族两个 getter 的越界策略不同**。
⚠️ partial：宿主类、this+0x16C 语义（「下一个可读索引」推断）、数组元素类型。

0x0048BEE0 —— 对象清理析构（36B）（5 callers，全 0x23=36B 读完；deps=48）
================================================================================
机器码（全 36 字节）：
```
0048bee0  push esi / mov esi, ecx
0048bee3  mov eax, [esi+0x20]              ; ★this+0x20（缓冲指针）
0048bee6  mov dword [esi], 0x7E51B4        ; ★★装虚表 0x7E51B4
0048beec  push eax / call 0x7C8B3D         ; ★★batch 001 operator delete
0048bef2  mov ecx, [esi+4]
0048bef5  add esp, 4
0048bef8  test ecx, ecx / pop esi
0048befb  je 0x48bf03
0048befd  mov edx, [ecx] / push 1 / call [edx]   ; ★虚表槽 0（带参 1）
0048bf03  ret
```
语义：**对象清理析构（推断名）**——入口先**装虚表 0x7E51B4**，再释放 `+0x20`
持有的缓冲（`operator delete`），最后对 `+4` 持有的对象经**虚表槽 0** 带参 1 调用
（自删除语义）。
★原版怪癖（照抄）：① **装虚表发生在释放之前**（析构入口改虚表——C++ 析构标准
形态）；② `+4` 成员**走虚表槽 0 + push 1**（而非直接 delete——持有的是多态对象）；
③ 本函数**无栈帧**（不 sub esp，只用 push esi）。
★跨批次连接：**0x7C8B3D（batch 001 —— C++ operator delete，本条=释放现场）**；
**虚表 0x7E51B4 新登记**（本对象类型标识）。
★邻函数：`0x0048BF10` 起为**另一函数**（`xor eax,eax / mov [ecx+0x34],eax /
[ecx+0x38] / [ecx+0x3c] / [ecx+0x40]`——连清四个字段的 reset），说明本条边界
干净（36B 后即 `ret` + 12 个 `nop`）。
⚠️ partial：宿主类、`+0x20` 缓冲类型、`+4` 持有对象类型、虚表槽 0 方法名、
虚表 0x7E51B4 对应类名。

（batch 371 说明：C++ 模型决策）
================================================================================
本批三函数**不新增 C++ 模型**，理由：
① 0x0052AEC0（三字段构造器 19B）——三字段清零是任何宿主类的 trivial 构造，
   重写时按目标类布局内联即可，无语义分支可测。
② 0x00557AC0（带钳制 getter 30B）+ 邻函数 0x00557AE0——**本条价值 = 两个同族
   getter 的越界策略不同（钳制 vs 判空返 0）**，是「原版容错形态」的取证记录；
   其行为只依赖宿主字段（+0x44/+0x38/+0x16C），脱离宿主无法单测。
③ 0x0048BEE0（清理析构 36B）——析构序列（装虚表 → delete → 虚表槽 0）属宿主
   类生命周期，重写时随目标类析构实现。
本批无产品代码改动，ctest 维持 **43/43 全绿**。登记三行全部 semantics_verified
（三函数全段字节读完 + 邻函数对拍 + batch 001 调用现场 + 虚表/常量核对），
推断名 partial 项如实标注。
