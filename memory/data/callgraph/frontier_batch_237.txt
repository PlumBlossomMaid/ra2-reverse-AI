0x487EE0 —— 四分量向量差值赋值（前两维取差、后两维直传）（7 callers，全 0x34=52B 读完）
================================================================================
机器码（全 0x34）：
    mov edx,[ecx+4]（★this->[+4]）
    mov eax,[ecx]（★this->[0]）
    push ebx/esi
    mov esi,[esp+0x10]（★参数2 = 输出向量*）
    push edi
    mov edi,[esi+4]（★参数2->[+4]）
    mov ebx,[esi]（★参数2->[0]）
    mov esi,[ecx+8]（★this->[+8]）
    mov ecx,[ecx+0xC]（★this->[+0xC]）
    sub edx,edi（★★差值分量1 = this->[4] - 参数2->[4]）
    mov edi,[esp+0x10]（★取回参数2）
    sub eax,ebx（★★差值分量0 = this->[0] - 参数2->[0]）
    mov ebx,edi（★edi = 输出指针）
    mov [ebx],eax（★★输出[0] = 差值 X）
    mov eax,edi（★eax = 输出指针）
    pop edi
    mov [ebx+4],edx（★★输出[4→+4] = 差值 Y）
    mov [ebx+8],esi（★输出[+8] = this->[8] 直传）
    pop esi
    mov [ebx+0xC],ecx（★输出[+0xC] = this->[0xC] 直传）
    pop ebx / ret 8（★2 参 stdcall 风格，ret 8 清 2 参）

语义：**四分量向量差值赋值（前两维取差、后两维直传）**——
`out[0] = this[0] - param2[0]`（X 差）、`out[+4] = this[4] - param2[4]`（Y 差）、
`out[+8] = this[8]`、`out[+0xC] = this[0xC]`（**Z/其余两维原样直传，不取差**）。
四分量结构（0/4/8/C 各一 dword）——坐标+高程类向量（3D 坐标用 4 分量补齐）。

★原版怪癖（照抄）：① **只对前两分量取差**，后两分量**直接拷贝 this 的原值**
（`mov [ebx+8],esi` 传入的是 `this->[+8]` 而非 `param2->[+8]`）——即差值
只作用于 X/Y，Z/第四维不变；② `esi` 寄存器被复用为「先存 param2、后存 this->[+8]」
——编译器寄存器分配产物，但语义确定：`[ebx+8]` 取的是 **this** 的 +0x8（不是参数）。
③ ret 8 = 2 参（this 走 ecx，另 1 参走栈 8B）。
★跨批次连接：4 分量坐标结构（+0/+4/+8/+C）——与 batch 236 的
`0x5F4D30` 坐标三字段（槽 0x48 取 x/y/z）同族（本条是第四维补齐版本）。
⚠️ partial：宿主类名（VectorClass 推断）、第四维语义（高程/朝向/w 或 pad）、
调用点的「取差 vs 直传」组合意图

0x755CD0 —— 对象构造器（清七字段 + 子构造 + 失败置错误位）（7 callers，全 0x37=55B 读完）
================================================================================
机器码（全 0x37）：
    push esi / mov esi,ecx（★this）
    mov ecx,[esp+8]（★★参数1）
    xor eax,eax
    mov byte ptr [esi],al（★+0x00 = 0）
    mov [esi+4],eax / mov [esi+8],eax / mov [esi+0xC],eax（★+0x04/+0x08/+0x0C = 0）
    mov [esi+0x10],eax / mov [esi+0x14],eax / mov [esi+0x18],eax（★+0x10/+0x14/+0x18 = 0）
    mov eax,[esp+0xC]（★★参数2）
    push eax / push ecx / mov ecx,esi / call 0x755DB0（★★★子构造 0x755DB0(this, 参数1, 参数2)）
    test eax,eax / jne 0x755D01（★子构造返回 0 → 跳过错标记）
    mov byte ptr [esi],1（★★失败：置 byte[this+0]=1 错误标志）
    0x755D01: mov eax,esi（★返回 this）/ pop esi / ret 8（★2 参）

语义：**对象构造器（清七字段 + 子构造 + 失败置错误位）**——把
`byte[this+0x00]` 与 `dword[this+0x04..+0x18]`（共 7 个字段：0/4/8/C/10/14/18）
**逐字段清零**（`xor eax,eax` 后连写 6 个 dword + 1 个 byte）→ 调子构造
`0x755DB0(this, 参数1, 参数2)` → 若其返回 **0（失败）**则置 `byte[this+0]=1`
作为错误标志 → 无论成败返回 this。

★原版怪癖（照抄）：① **`byte[this+0]` 是错误标志**（构造成功后为 0、失败置 1）
——「首字节即状态位」，与 batch 234 的 `+0x81` 完成位、batch 236 的 `+0x80/+0x81`
对形成同类「低偏移状态字节」惯用；② 失败标志**不复位**（不回滚已清的字段，也不调
析构）；③ 子构造返回值语义是「0 = 失败」（非常规的 NULL-means-error 约定——
MSVC `Create` 类 API 惯用返回值）。
★跨批次连接：低偏移状态字节族（batch 234 +0x81 完成位 / batch 236 +0x80+0x81 对 /
本条 +0x00 错误位）+子构造 `0x755DB0`（紧邻同区 0x755D10 是同族第二成员，
`push esi/xor edi,edi` 形态）。⚠️ partial：宿主类名（0x755xxx 区 UI/工具类推断）、
0x755DB0 子构造身份、0x00 错误位的消费端（读点未追）、参数1/参数2 语义
