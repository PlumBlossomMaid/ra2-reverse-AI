地图真实尺寸的四张插值表 + side 推导
取证日期 2026-08-06 / 来源 gamemd.exe (ImageBase 0x400000) 只读分析

== 谁用 ==
阶段 1 Init random map @0x599650 开头 0x599665-0x599727。
产出写进 MapSeedClass +0x180 (W) / +0x184 (H)，
下游全部阶段公式里的 [0x87F8DC]=W / [0x87F8E0]=H 就是它俩。

== 输入 ==
MapSeedClass +0x64 Width   .sed 里的滑条档位（实测样本 = 0），不是格数
MapSeedClass +0x68 Height  同上
MapSeedClass +0x50 NumPlayers   表下标 = NumPlayers - 2
MapSeedClass +0x3C MapType      决定要不要夹取，且触发一条怪癖

== 常数 ==
0x7ED968 = 0.3333333432674408f (raw 3eaaaaab)   即 1/3，单精度
0x7E2AC8 = 1.0f                (raw 3f800000)
0x7E5190 = 1.2                 (raw 3ff3333333333333) double，夹取上界

== 四张表（.rdata，各 7 项 int32，下标 = NumPlayers-2） ==
VA         表    2P  3P  4P  5P  6P  7P  8P
0x7ED634   wLo   70  70  70  80  90 100 100
0x7ED650   wHi   80  80  80  90 100 110 120
0x7ED66C   hLo   70  70  70  80  90 100 100
0x7ED688   hHi   80  80  80  90 100 110 120
（宽高两组逐项相同；0x7ED6A4 = 0，表到此为止）

原始 dump（read_const.py dword，0x7ED634 起连续 29 个 dword）：
70 70 70 80 90 100 100 | 80 80 80 90 100 110 120 |
70 70 70 80 90 100 100 | 80 80 80 90 100 110 120 | 0

== 算式 ==
idx = NumPlayers - 2
wt  = (float)Width  * (1/3f)
ht  = (float)Height * (1/3f)
if (MapType != 3 && MapType != 4) { wt = min(wt, 1.2); ht = min(ht, 1.2); }
W = _ftol( wLo[idx]*(1-wt) + wHi[idx]*wt )
H = _ftol( hLo[idx]*(1-ht) + hHi[idx]*ht )
_ftol = 0x7C5F00，RC=chop，向零截断

== MapType 3/4：跳过 1.2 夹取（不是「宽度用了 ht」）==
0x59968D  cmp eax,3 / je 0x5996D7   ; 3/4 直接跳过整段夹取
三条路径 0x5996CD / 0x5996D5 / 0x5996D7 都汇合到 0x5996DB，
且都把 ht 留在 x87 栈顶；0x5996D7 的 fld [esp+0x10] 就是 ht 本身，
它是给「高度」插值用的（0x599713 fsub st(2) / 0x59971E fmul st(2)），
「宽度」插值读的是内存栈槽 [esp+0x14] = wt。

后果：夹取被跳过 -> wt/ht 可超过 1.2，插值变外推，地图可比表里的 Hi 更大。
模拟执行真值（2 玩家）：
  档位   MapType=1   MapType=3/4
   3        80          80
   4        81          83
   5        81          86
   6        81          90

精度不对称（照抄，不要"统一"）：
  wt 夹取后 fstp dword 回落 float 再重新读入；
  ht 夹取后始终留在 x87 栈上保持 double。
  已构造两个模型（ht 回落/不回落）各 8960 例与原版对拍，均 0 例不一致——
  该差异在当前取值域内观察不到，但汇编就是不对称的。

== 已推翻的推测（留档，防止再犯）==
曾把 0x5996D7 的 fld [esp+0x10] 读成「MapType 3/4 时宽度误用 ht」，
并当成复制粘贴 bug 登记进 CLAUDE.md 怪癖清单。
模拟执行证伪：固定 Width=0 只动 Height，MapType=3 下 W 恒为 70。
错因：只看单条指令没跟 x87 栈。凡涉及 x87 栈的结论必须模拟执行验证。

== side = W + H + 1 ==
0x42AC00（由 0x685198 push 0x87F8D4 / 0x6851A7 call 进来）：
  0042ac56  mov  ecx, [eax + 0xc]     ; rect.Height
  0042ac59  mov  edx, [eax + 8]       ; rect.Width
  0042ac5c  lea  eax, [ecx + edx + 1]
  0042ac60  mov  [0x89c2dc], eax      ; side
  0042ac65  imul eax, eax             ; side²
  0042ac68  lea  edi, [eax*4]         ; 四个 side² 的 int 数组，随后 4 次 operator new
= 等距菱形的外接正方形边长（等距 X = rx+ry+1 的上界）。
这解释了工作数组为什么是 side×side 方阵。

同一函数填的八邻域展平步长（0x42AC93-0x42ACE3）：
0x89A304 = -side      0x89A308 = 1-side     0x89A30C = 1        0x89A310 = 1+side
0x89A314 = side       0x89A318 = side-1     0x89A31C = -1       0x89A320 = -1-side

== 未确认 ==
谁把 MapSeedClass +0x180/+0x184 搬进 [0x87F8DC]/[0x87F8E0]。
0x87F8DC/0x87F8E0 全镜像只有 0x68555A/0x685560 一处写，而那里是
xor eax,ecx,edx,esi 之后的一次性清零，真正的赋值路径没跟到。
两者数值相等由下游全部公式的自洽性佐证。

== 对拍状态 ==
纯有理数模型（Fraction + 显式 chop 到 24/53 位）对模拟执行 8960 例
（NumPlayers 2..8 × MapType 0..4 × Width 0..15 × Height 0..15）：0 例不一致。
模型要点：
  fild dword          精确
  fmul dword 1/3f     double 精度 chop（PC=53/RC=chop）
  fstp dword          落 float，chop 到 24 位
  min(x, 1.2)         1.2 是 double 0x3FF3333333333333
  _ftol               向零截断
